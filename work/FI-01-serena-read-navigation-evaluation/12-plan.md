## 개선 조건의 모델용 테스트 지침

- 터미널 검색과 파일 읽기를 자유롭게 사용한다. 기존 files/search/read_file도 차단하지 않는다.
- 파일 전체를 읽을지 결정할 때 터미널로 800줄 초과 여부를 확인한다. 이미 확인했고 파일이 바뀌지 않았다면 재확인하지 않는다. 여러 파일은 한 호출로 확인할 수 있다.
- 800줄을 초과하는 코드 파일은 함수 검색(list_ids)과 선택한 함수 본문 조회(read_symbols)를 사용한다. 필요한 함수가 여러 개면 한 호출에 묶는다. ID를 이미 알면 목록 조회를 생략하고 본문을 직접 읽을 수 있다.
- 800줄 이하 파일은 작업에 필요하면 터미널로 전체를 읽을 수 있다. 전체 읽기는 의무가 아니며 관련 구간 검색도 가능하다.
- 함수 조회로 얻을 수 없는 import·상수·설정·함수 밖 코드는 큰 파일에서도 필요한 구간을 터미널로 읽을 수 있다. 도구 오류나 미지원 파일은 터미널로 조사하고 그 사용을 측정에서 제외하지 않는다.
- 기존 ID·시작/끝 줄·시그니처·기존 문서 주석의 첫 문장(있을 때)을 최초 목록 응답에 함께 제공한다. 추가 정보를 펼치는 별도 호출이나 필수 단계를 만들지 않는다. 목록 정보와 함수 본문 조회는 구분한다.

Windows PowerShell에서 사용 가능한 판별 예:

```powershell
rg -c -m 801 --include-zero -H '^' 파일경로
```

801이면 800줄 초과다. 읽기 오류는 작은 파일로 처리하지 않는다. 기본 텍스트 판별 기준이며 binary/encoding 오류와 한 줄 압축 파일은 별도 처리 여부가 아직 미정이다.

## 함수 목록 정보 — current (실험용 JS/TS adapter)

- 기존 ID 유지.
- 시작 줄·끝 줄을 제공한다. 줄 번호는 1부터 시작하는 양끝 포함 범위다.
- 시그니처를 제공한다. 원문에 있는 이름·매개변수·타입·기본값·반환 타입·async 등 선언 정보를 추출하며 함수 본문은 포함하지 않는다. 원문에 없는 타입이나 설명을 추론해 생성하지 않는다.
- 해당 선언에 연결된 기존 문서 주석이 있으면 첫 설명 문장을 함께 제공한다. 문서 주석이 없으면 설명 항목은 생략한다. 주변의 임의 주석이나 Agent가 새로 작성한 역할 설명으로 대체하지 않는다.

- 선택적 펼치기는 제공하지 않는다. 위 메타데이터는 한 번에 제공한다. 함수 본문 전체를 목록에 포함한다는 뜻은 아니다.
- v1은 ID만 반환하고 v2는 위 메타데이터를 제공한다. 제품 기본 도구에는 등록하지 않는다. 문서 요약은 compiler-attached JSDoc의 마지막 block에서 tag 이전 첫 설명 단락의 첫 문장(.!?。！？ 뒤 공백/끝 기준)이며 약어 특례는 없다.

## 후속 비교의 보존 조건

기존 조건과 개선 조건 모두 터미널을 허용한다. 함수 도구가 없는 기존 조건에는 사용 불가능한 도구 사용 지시를 넣지 않는다. 따라서 개선 조건의 도구와 읽기 지침을 묶은 효과를 측정하며 도구 단독 인과효과로 보고하지 않는다.

줄 수 확인·터미널 읽기·검색·ID 목록·본문 조회를 모두 계측한다. 전달 출력, 컨텍스트 증가, 누적 입력 토큰, 모델 요청 수, 조회 횟수, 정확성을 별도 비교한다. 터미널로 읽은 출력이나 재시도를 제외하지 않는다.

## 구현·검증 범위

- 실험용 v2만 추가한다. 기존 v1 소스·테스트·결과를 유지하며 공통 read_symbols 계약을 상속한다. v2 list_ids 응답은 {id,start_line,end_line,signature,doc?} 배열이다.
- JS/JSX/CJS/MJS/TS/TSX/CTS/MTS는 설치된 TypeScript AST와 실제 Serena 심벌 위치를 재사용한다. 한 파일의 metadata는 한 번 파싱한다. 현재 실험 범위 밖 언어에는 허위 signature를 만들지 않고 미지원 오류를 명시한다.
- 언어·소스 메타데이터 의미는 공통이나 실제 검증 환경은 Windows x64, Python 3.13, Node, Serena 2.1 및 기존 TypeScript 설치다. Linux/macOS·기타 언어·실제 앱 화면·전체 제품 빌드 수용을 주장하지 않는다.
- root가 과제·정답·계약·통합·최종 수용을, v2_reader_impl이 신규 v2 adapter/helper/test를, minimal_reader_tests가 격리 환경·backend·계측·정리를 소유한다. 자식 위임은 하지 않는다.

## large 과제 독립 판정 기준

정답은 원본 App.tsx의 estimateTableColumnWidth와 해당 helpers/constants에서 정한다. 이 기준은 trial guide에 전달하지 않는다.

- 처음 50행을 샘플링하고 렌더링된 표시 문자열의 공백을 정규화해 길이를 잰다. 빈 표시 문자열은 cellLengths에서 제외한다. label 길이를 함께 넣어 정렬한 뒤 ceil(n×0.9)-1 인덱스(범위 보정)의 p90을 사용한다.
- column.format 또는 숫자/통화/percent 타입은 numeric으로 취급한다. 그 외에는 null/빈 문자열을 건너뛴 샘플에서 asNumber로 해석 불가한 값이 하나라도 있으면 false, 관측값이 없으면 false다. 숫자형 문자열은 쉼표 제거와 finite 검사를 거친다.
- 장문은 field/label의 comment/description/detail/explanation/insight/interpretation/note/reason/summary 키워드 또는 최대 길이>34, 날짜는 date/day/month/quarter/week 키워드로 판단한다. 분기 우선순위는 content→숫자→날짜→장문→일반이다.
- 문자 폭 계수는 숫자 7.2, 그 외 7.4이고 가로 padding은 24에 dense면 16을 더한다. 목표 길이×계수+padding을 올림한다.
- content는 min(max(label,p90),28), clamp 88..240이다. 그 외 목표 길이는 일반 max(label,p90), 장문 min(max(label+4,p90),44)다.
- 숫자는 percent 최소96/그 외108, 최대136; 날짜116..156; 장문220..260; 일반은 기본112/dense124..220이다. dense는 padding과 일반 최소 너비에 영향을 준다.
- 근거 함수/상수 위치를 제시하고 실제 화면·제품 테스트 실행을 주장하지 않는다. 중요한 분기·수치 오류 또는 근거 부족은 그대로 기록하며 답변 길이 자체를 점수로 삼지 않는다.
