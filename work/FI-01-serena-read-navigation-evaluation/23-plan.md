# v5 단순 방식 1회 측정

## 목표와 승인

사용자는 기존 완료 결과를 확인한 뒤 v5 실험도 진행하도록 승인했다. 직전22의 v5 미완료와 별개로 이번 actual v5 trial1회만 허용되며 기존 조건 재실행0이다. 새 캐시 감시·자동 중단·공식 캐시 진단·loopback probe·제품 engine 수정/빌드/배포는 범위 밖이다. 기존21의 단순 native 하네스·v5 계약을 재사용하고 모델 OpenAI/gpt-6.1-sol/medium, 자유 terminal, 파일크기 제한 없음, 효율적 사용 한 문장만 유지한다.

## 비교와 범위

가능하면 직전22의 동일 frozen corpus를 읽기전용 소비해 새run으로 고정 복사한다. 새입력은 SHA와 공통핵심2파일·v5 의존9개를 확인하고 동일 unit/native 수용 근거를 재사용한다. 기존22의 baseline1회 완료(누적204,450/일반35,362/캐시169,088/출력2,306/전달45,787자/증가13,282/요청7/도구6/105.326초)를 비교 대상으로 사용한다. 그 baseline은21 developer에서 도구 효율 안내 한 문장 제거와 dynamicTools=[]인 현행 no-reader 조건이며 역사적12와 프롬프트 전체 동일 복원은 불가했다.

JS/TS 조사 의미는 공통이며 실제 검증환경은 Windows x64 로컬 설치 runtime이다. 다른OS·기본 제품 등록·UI검증은 범위 밖이다. 사용자 VS Code가 종료된 원인은 미확정이고 이번 성공 여부로 그 원인을 설명하지 않는다.

## 최소 실행과 책임

root가 계약·수용·최종commit을 맡고 기존 runner가 소유된 새run의 준비/실행/측정/독립기록/정리를 맡는다. 재위임0, 타인 source/staged 변경 보존. 우선 이전producer 잔존과 현재host 자원·같은corpus/engine 재사용 가능성을 읽기전용 확인한다. 기존22의 session 관측권 소실·actualexit unknown을 유지하며 PID부재만으로 기존run 삭제를 허용하지 않는다. 새producer를 중복 실행하지 않는다.

root가 읽기전용 재사용 조사와 최소 실행 범위를 수용했다. 최소engine1개·backend1개·thread1개 준비 및 선행조건 확인 뒤 실제 v51회 실행을 조건부로 승인했다. 별도의 READY 승인 대기는 추가하지 않는다. 정상 kmw owner 재사용 외 계정조작·credential복제·공유설정변경은 하지 않는다. 설치 준비와 실제 model START를 구분하고, 아래 선행조건이 모두 맞으면 runner가 root의 명시적 실행 승인에 따라 exclusive START를 생성해 v51회만 진행한다. 선행조건은 source643/deps9/core2/runtime SHA 동일, v5 prompt/tool21 동일, OpenAI/gpt-6.1-sol/medium, 정상 kmw active, 공유 설정/계정 switch0, 이전 소유 producer 중복없음, source/control 시작 전 불변 확인이다. 실패 시 추가 producer/모델 재시도 없이 중단한다. 복잡한 감시·별도 추가진단은 제거하고 이전21의 단순한 사용량/도구 출력 분석을 유지한다.

## 수용과 보고

고정 input/control 재확인, 정확한 actual exit와 관측 process tree 종료, 최종 답변·정확도, 고유 response ID별 usage와 실제 도구 응답으로 수치를 확인한다. 모델 전달 출력·입력 증가·누적/일반/캐시/쓰기 입력·모델 출력·요청/도구 호출·모델시간을 비교한다. 캐시와 API 환산 비용은 변동 가능한 참고값이며 첫 요청을 별도 보고한다. 중단된22 v5 부분값을 정상 완료값과 비교하지 않는다.

## 산출물과 정리

새producer 전에 owner/lifecycle와 planned 산출물을 등록한다. 새run 원문은 최소 독립수용 근거·실제하네스 소스·전체 manifest·검증/종료근거를23-verification.json으로 보존한 뒤 root 수용 후 owner close/refrelease/register-review-delete-finalize를 적용해 실제 삭제를 확인한다. sr04 기존 보관 승인을 유지하고 새run 참조만 해제한다. 기존22의 불명 종료 보호자료는 별도 미해결로 유지하며 임의삭제하지 않는다. task commit은 새작업 경로만 포함한다.
