# 요구사항과 승인 범위

현재 목표·요청 산출물·허용 작업·확정 결정·미결 사항을 먼저 판단한 뒤 두 진입 방식 중 선택한다. 답변에 따라 설계를 발전시켜야 하면 design-collaboration, 조사 후 질문과 접근 방법을 계획에 모을 수 있으면 development-workflow다. implementation은 승인된 계획과 실행 범위를 이어받는다. 전문 스킬의 선택이나 주제 언급만으로 단계·권한을 확대하지 않는다.

설계와 계획을 같은 작업 기록에서 이어가고, 이해 통일 문서를 필수 선행 단계로 만들지 않는다. 계획에 질문·추천안·영향을 적으며 대화로 링크와 결정할 핵심을 알린다. 작은 작업은 짧은 계획을 작성하고 불필요한 승인 대기를 추가하지 않는다. architecture 차이는 사전 검토하며 새 사실은 영향받는 변경분만 검토한다.

architecture의 합의된 기능과 기존 코드·테스트·실제 동작을 보존한다. 오류 회피를 위한 삭제·숨김·비활성화·검증 축소는 범위 변경이며 사전 검토한다. 문서의 부재는 삭제 권한이 아니고 draft 제안과 합의된 설계를 구분한다.

# 실행·소유권·검증

root가 instructions/의 공통 진입 지침과 5개 스킬의 관련 본문·설명·참조·bootstrap 템플릿·예시, 프로젝트 Work 안내와 architecture/instructions.md의 관련 계약을 갱신한다. 활성 설치본의 관련 부분을 동기화하고 SKILLS-SOURCE.json을 갱신한다. 파일 경로가 변하지 않으면 component mapping은 유지하고 기존 검사로 확인한다. 기존 설치본의 별도 지침과 다른 작업 변경은 보존한다. 앱 코드·패키징·배포는 범위 밖이다.

변경은 공통 지침이며 실제 파일 검사 환경은 Windows다. 스킬 형식 검사·라이브러리/링크/manifest 검사·설치본 일치 검사·이번 작업 diff 검사를 수행한다. 역할 간 충돌과 대화 사례의 기대 행동은 문서로 대조하되 실제 모델 행동을 검증했다고 보고하지 않는다. 실사용 테스트와 그 결과에 따른 추가 보완은 사용자가 후속 수행한다.

# 결과

공통 진입 규칙과 5개 스킬의 역할·설명·본문, 관련 참조와 bootstrap 템플릿·예시를 일치시켰다. 계획은 두 진입 방식에서 같은 기록을 사용하고 작은 작업은 짧게 정리한다. 질문은 문서에 두고 대화에서 링크와 결정할 핵심을 알린다. architecture와 코드·테스트·동작 근거로 기능을 보존하며, 기능 축소와 승인되지 않은 설계 차이는 관련 구현 전에 검토한다. 지속적인 계약은 docs/architecture/instructions.md의 관련 절에 반영했다.

활성 설치본의 스킬 리소스 9개를 동기화했다. 전역 AGENTS.md는 Work Entry 절만 변경하고 나머지 내용은 보존했다. SKILLS-SOURCE.json의 크기·해시를 갱신했으며 경로 변동이 없어 기존 component mapping을 유지했다. 초기 검사에서 bootstrap playbook 템플릿에 직접 구현 진입 문구가 남은 것을 찾아 수정했고 최종 충돌 검색에서 해당 문구가 없음을 확인했다.

실사용 확인 사례와 기대 행동:

| 상황 | 기대 행동 |
| --- | --- |
| 설계 중 스킬 수정 필요성 언급 | 설계 요구사항에 반영하고 실행 범위를 확대하지 않음 |
