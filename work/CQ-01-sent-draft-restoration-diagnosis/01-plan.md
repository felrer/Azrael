# 전송 후 세션 초안 복원 조사

요청: 전송 뒤 다른 세션을 방문했다 돌아올 때 입력 문장이 복원되는 것이 저장 초안 미삭제 때문인지 확인한다. 허용 범위는 코드 및 읽기 전용 동작 조사이며 제품 변경은 포함하지 않는다.

범위: 공통 webview 전송·초안 로직. Windows 설치 파일과 Node fixture에서 확인했다. 실제 UI 세션 전환, Linux/macOS 및 해당 대화의 저장 상태는 미검증이다.

## 확인 근거

- `scripts/inject-composer-draft.cjs`의 `__azraelComposerSnapshot`은 텍스트·저장 초안뿐 아니라 attachments, selections, apps를 함께 비교한다.
- `__azraelRelease`는 입력창을 비운 직후 스냅샷과 현재 상태의 일치 여부를 `Fyr` 해제 콜백에 전달한다.
- 같은 파일의 `Fyr` 변환은 불일치 시 retained 참조만 해제하고 저장 초안을 삭제하는 `NG(...discardRetainedDraft:true)` 실행 전에 반환한다.
- 원본 `Bba`는 화면을 비우고 `Gyr`를 호출한다. 원본 `NG`는 retained 초안이 있는 동안 빈 값 저장을 생략한다. 따라서 성공 시 해제 단계가 저장 초안 삭제를 맡는다.

## 재현 및 한계

기존 `scripts/test-composer-draft.cjs`를 메모리에서 로드해 전체 변환 전송 함수와 실제 retained 해제 함수를 실행했다. 파일·사용자 대화·저장 설정을 변경하지 않았다. 기존 fixture의 editor/controller/atom/persistence adapter를 이용했다. 테스트 파일을 추가하거나 수정하지 않았다.

1. 일반 성공: 입력창 빈 문자열, 저장 초안 없음, 오류 없음.
2. 최초 clear 후 `xW` 선택 세대 atom을 변경한 다음 성공 콜백 실행: 입력창 빈 문자열, 저장 초안 A 유지, retained 참조 해제, 오류 없음.
3. 결과 명령 종료 코드 0.

이 재현은 성공 전송 뒤 저장 초안이 남는 코드 경로를 입증한다. 실제 화면에서 어떤 스냅샷 필드가 바뀌었는지, 초안 복원이 정확히 같은 경로였는지는 UI 및 해당 세션 저장소를 관찰하지 않았으므로 단정하지 않는다. `xW`의 실제 변경 경로에는 실행 위치 전환 및 신규 대화 위치 의존성 변화가 있다. 기존 대화에도 다른 비교 필드 변화가 가능하나 실제 발생은 미검증이다.
