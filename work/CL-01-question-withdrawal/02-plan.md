# Cargo 검증 사전 검사 관문

상태: 구현·관련 검증·산출물 보관 처리 완료. 설치·배포·타 플랫폼 검증은 제외하며 태스크 커밋은 보류한다.

## 목표와 범위
기존 Cargo 검증 도우미와 검증 묶음 정의에 실행 관문을 추가한다. 관련 타입·테스트 준비 검사가 실패하거나 지정 필터가 테스트 0건을 선택하면 후속 테스트 실행과 성공 근거 생성을 막는다. 기존 Cargo 캐시·실행 소유권·검증 결과 재사용을 유지하고 별도 중복 캐시를 만들지 않는다. 테스트 준비용 컴파일과 실제 테스트를 구분한다.

Windows x64/Linux x64/macOS ARM64 공통 의미이며 실제 검증은 Windows에서 수행한다. 제품 빌드·설치·배포, 기존 엔진 소스와 스키마 기준 수정은 제외한다. 공유 파일의 기존 변경을 보존한다.

## 구현과 검증
루트가 Cargo 도우미·실행 관문·묶음 정의·관련 테스트와 소유 문서를 맡는다. 기존 조사 에이전트는 캐시·묶음 연결 경계만 읽기 전용으로 확인한다. 기존 표준 Node/Cargo와 관리 실행 경계를 재사용한다. 사전 검사 선언 누락·실패·0건·시그널·입력 변경 및 유효 근거 재사용을 집중 검증하고, 작은 실제 Cargo fixture로 실행 순서와 반복 컴파일 방지를 확인한다. 대형 엔진 재컴파일은 이 변경의 기본 검증으로 선택하지 않는다.

## 산출물과 완료
태스크 소유 로그·fixture는 실행 전에 기존 artifact lifecycle에 등록하고 종료 후 검토해 삭제 또는 보류한다. 검증 결과와 실제 종료 코드, 타 플랫폼 미검증, 기존 작업과 분리할 수 있는 커밋 여부를 이 문서에 기록한다.

## 구현 결과와 검증 기록
- `runCargoTest`에 `selected-tests-v1` 관문을 연결했다. 같은 입력·설정의 `cargo check`(테스트 타입 포함), 원래 필터의 목록, 실제 실행 순서다. 테스트 0건·오류·중단이면 후속 실행을 막는다. 기본 test profile을 명시하고 Cargo incremental과 기존 검증 결과 캐시를 재사용한다. 별도 사전 검사 캐시는 추가하지 않았다.
- 두 우회 경계도 연결했다. task recovery는 `capture:true`로 실제 통과 건수 검사를 유지한다. Windows PTY/daemon은 타입 검사와 직접 목록 확인 뒤 기존 detached 실행을 유지한다. 단계별 실제 종료 코드와 선택 수를 로그에 남긴다.
- Cargo native 검사 27개가 명시적 정책을 선언하며, 누락·지원하지 않는 정책을 묶음 검증에서 거부한다. 도우미 내용과 전체 check 선언은 기존 캐시 key에 포함되어 예전 성공 근거를 무효화한다.
- 실제 manifest 검증 중 이전 질문 기능의 UI feature에 native check가 섞여 기존 검증기가 거부함을 발견했다. native/SDK 검사를 `engine.question-withdrawal`로 옮기고 모든 check ID와 검사 범위를 유지했다. UI source 검사는 기존 `ui.question-withdrawal`에 유지한다. 실제 manifest 전체 검증이 통과했다.
- 작은 실제 Cargo fixture의 정상·반복·통합·0건·타입 오류 5사례는 exit 0으로 통과했다. 예상 차단의 내부 종료 코드는 1/101이다. 첫 실행 12.7초 대비 동일 입력 반복은 1.0초였고 재컴파일은 없었다. 작은 fixture의 실측이며 전체 엔진 절감 시간으로 일반화하지 않는다. 최종 코드로 재검증한 `accepted-real.log`도 exit 0이다.
- 초기 단위 검사 실패 2건은 mock 호출 인덱스와 새 단계 수 기대값을 수정했다. mock 실패·중단이 남긴 미확인 lease를 삭제하지 않고 독립 fixture로 재시도했다. 초기 통합 검사 91건 중 86통과/5실패는 SDK venv Python 3.10이 기존 config parser의 3.11+ 요건에 맞지 않은 실행 준비 오류였다. 설치된 Python 3.13.15를 확인한 뒤 재검증했고 캐시 단독 17건은 exit 0이었다.
- 최종 통합 96건, 실제 Cargo 5사례 모두 exit 0으로 통과했다. 입력 12개 해시가 검사 전후 일치한다. `cargo-preflight-1/logs/verification-summary.json`에 실제 종료 코드와 로그를 기록했다. 전체 통합 검사는 약 97초였으며 Cargo config 캐시의 기존 Python 기반 검사 비용이 대부분이다.
- 제품 빌드·설치·배포·대형 엔진 재컴파일·다른 OS 검증은 실행하지 않았다. 기존 변경이 섞인 feature/config/docs를 통째로 포함할 수 없으므로 Work 예외에 따라 태스크 커밋은 보류한다. Git index는 변경하지 않았다.
- 최종 lifecycle 등록·검토·보류 적용이 완료되었다. 재현용 입력과 로그 약 13 MB를 대체 검증 또는 승인된 릴리스 근거가 보존될 때까지 유지한다. 등록 전 테스트가 만든 junction 10개만 일반 비재귀 삭제하고 각 대상 디렉터리와 내용이 보존됨을 확인했다(`logs/junction-cleanup.json`). 새로운 worktree는 만들지 않았다.
