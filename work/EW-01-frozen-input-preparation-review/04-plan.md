# 선택 소스 검사 정리

## 목표와 권한
기존 121개 소스 검사를 testing 지침의 반복 실수 기준으로 검토한다. 단순 존재·문구·내부 구조 확인으로 남은 검사는 삭제하고, 향후 작업에서 다시 빠뜨릴 구체적 호출·등록·설정 전달 검사는 최소 범위로 남긴다. 자동 검증 축소이며 제품 기능·필수 인수 결과를 삭제한 것으로 표현하지 않는다. 제품 코드·공유 지침·전체 빌드·설치·기존 고정 입력 변경은 제외한다.

## 실행·검증
Root는 선택 정책·소비자·보존 inventory·통합·최종 삭제 판단을 맡는다. 읽기 조사자는 121개 목록을 40/40/41개로 나눠 독립 조사하며 수정·재위임하지 않는다. 보고서가 준비되는 범위부터 삭제를 적용한다. 변경 파일과 현재 동시 변경을 해시/상태로 고정하고 보존한다. 삭제된 테스트의 참조·fixture 소비자를 확인하고 영향 검사만 Windows에서 실행한다. 파일 수 감소를 시간 절감 실측으로 해석하지 않는다. 결정·근거·실행 증거는 11-source-test-retirement.json에 기록한다.

## 적용 결정

- 기존 121개 목록의 현재 파일을 조사했다. 파일 전체를 삭제할 근거는 확인하지 못했으며, 실제 동작·설정 연결·빌드 소유권 검사가 섞인 파일은 유지했다. 이 판단을 모든 남은 사례의 영구 필요성이 입증된 것으로 확대하지 않는다.
- 그룹 A: 19개 파일, 소스 문장 23개/동적 등록을 펼친 사례 34개 삭제. parser·idempotence·손상 anchor·고정 치환 수·무관 입력 동일성만 확인하는 독립 사례다. 기존 동작·cache 입력·asset 등록 검사는 유지한다.
- 그룹 B: 16개 파일, 소스 문장 24개/등록 사례 25개 삭제. 나머지 동작 검사와 cross-injector 조합, native list 비변경, 인수 전달 검사는 유지한다.
- 그룹 C: URL safety·Webview drag·Window Control 3개 파일에서 독립 소스 guard 사례 3개 삭제. 실제 pinned host, 동작, 등록·전달 검사는 유지한다. 구형 fixture 사례 삭제는 제품의 구형 입력 지원을 폐기한 것이 아니다.
- 합계는 38개 파일/등록 사례 62개다. 자동 검사 범위를 의도적으로 축소했으며 같은 검사를 setup이나 새 테스트로 옮겨 동등 검증이라고 주장하지 않는다. 파일 선택 정책과 feature check ID·경로는 변경하지 않는다.
- UI diagnostics는 삭제 사례 안의 변환 결과가 남은 직렬화·메타데이터·state/consume·renderer 동작 검사에서 필요했다. 준비만 별도 setup으로 유지하고 삭제한 assertion은 되살리지 않았다. 이 변환 시간은 없어지지 않는다.
- file-open-menu의 검증용 cache 정리에서 기존 force 옵션을 제거했다. 원래 owned 임시 경로의 일반 삭제를 사용하며 실패를 숨기지 않는다.
- 소스 범위 운영 문서와 upstream preservation 문서의 예전 assertion 유지 표현을 현재 축소 범위에 맞췄다. 제품 변환기의 unknown/duplicate anchor 거절과 최종 제품 인수 요건은 유지한다.
