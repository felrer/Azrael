# 사진 편집 결과 교체와 빈 그림 저장

채팅 입력창의 사진을 편집하면 원래 첨부를 같은 위치에서 교체하고 중복 첨부를 만들지 않는다. 그리기 전 상태, 모든 선을 지운 상태 및 변경 없는 상태도 사진 배경을 포함하여 저장한다. 기존 사진을 다시 편집하면 native 스케치 상태가 보존한 원본 배경과 편집 가능한 그림을 재사용한다. 일반 빈 스케치의 기존 저장 정책은 유지한다.

공통 웹 UI 수정이며 Windows x64, Linux x64, macOS ARM64에 같은 의미를 적용한다. 실제 소스 및 Chromium 렌더 검증은 Windows에서 수행한다. 과거에 전송한 메시지의 원본 첨부 이력, host 권한 및 사용자 설정을 변경하지 않는다. 전체 제품 빌드·설치는 이번 요청 범위에 포함하지 않는다.

기존 native `replaceUploadId` 첨부 교체 및 `openAttachment` 재편집 경로를 재사용한다. root는 injector·회귀 검사·문서·최종 수용을 담당하고 읽기 전용 담당자는 첨부 ID/교체 계약을 조사한다. 기존 렌더 fixture 담당자는 실제 native composer와 첨부 목록을 이용한 교체·빈 그림 저장 검증을 준비하며, 준비된 결과로 root가 밝은/어두운 테마를 확인한다. 다른 작업의 변경은 보존한다.

수용 기준: 선택한 사진만 교체되어 첨부 수와 다른 첨부 순서가 유지된다. 저장 실패 시 원본 첨부와 그림을 보존하고 재시도할 수 있다. 처음부터 그리지 않은 사진, 모든 선을 지운 사진, 변경하지 않은 재편집도 저장된다. 동일 첨부 재편집에서 배경을 합성한 결과를 다시 배경으로 평탄화하지 않는다. 다른 scope 거부, 취소, plain sketch, 기존 확대·닫기·다운로드를 보존한다.

검증 산출물은 `artifacts/tasks/BN-01-image-sketch/runs/replace-edit-20261019`와 별도 렌더 run에 귀속한다. 실패·통과 로그와 검증 화면은 검토 후 보존 여부를 결정하고 브라우저 profile과 검증 서버는 종료·삭제를 확인한다.
