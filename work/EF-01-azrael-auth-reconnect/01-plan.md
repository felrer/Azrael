# Azrael 기존 인증 재연결

- 목표/권한: Windows 로컬 pi-harness-init 창을 기존 인증으로 연결. 다른 창 종료, 인증 교체/삭제, 제품 코드 수정 없음.
- 기존 bridge 조회는 현재 대화의 창 컨텍스트를 상속할 수 있으므로 대상 창의 인증 성공을 입증하지 않는다. 조회 결과 ChatGPT Pro 활성 계정, lastError=null, 진행 중 턴 존재, 종료 코드 0.
- 사용자 증거: 로그인 시 다른 Azrael 창의 인증 점유 오류. 초기 화면 문제라는 기존 추정은 불충분하다.
- 근거: docs/architecture/accounts.md는 기존 계정의 여러 창 선택을 허용하며 인증 교체/로그인에는 배타적 점유를 요구한다. account_mutation_error의 WouldBlock이 해당 오류를 반환한다.
- 기존 구현: accountView.ts의 quickPick은 저장 계정 선택 시 switch를 호출한다. 계정 추가는 loginStart를 호출하는 별도 경로다.
- 다음 단계: 대상 창 하단 계정 상태 항목에서 기존 저장 계정 선택, 또는 계정 및 사용량 화면에서 기존 계정 전환. 대화 입력 화면 표시로 연결 확인. 실패 시 해당 오류를 추가 조사한다.
- 제약: Window Use 호스트 규칙의 Windows Codex 확장 UI 자동화 금지에 따라 화면 조작은 사용자 인계. 잠금 강제 해제나 인증 복사를 하지 않는다.
- 검증: 운영 상태 조회, 소스/계약 확인, 사용자 오류 화면. 대상 창 실제 연결과 추론 미확인. 제품 변경 없어 코드 테스트/설계 문서 수정 불필요.
- 정리: 작업용 인증 백업/복사/로그/스크립트 없음. 계획 입력 임시 파일은 삭제 및 부재 확인 완료.
