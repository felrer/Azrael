# ET-01 Windows x64 cache observation helpers

Task-local maintained source. Root owns registration, capture instantiation, product build/install and cleanup decisions. These helpers never delete cache files, release references, elevate, run arbitrary commands, or start product builds. Only Windows x64 and the installed WPR/.NET 10 environment are in scope.

## Analyzer contract

Run `dotnet <payload>/CacheAudit.dll <absolute-config.json>`. Config schema 1 requires `etlPath`, expected `etlSha256`, existing `reportRoot`, new `outputPath` contained beneath that root, unique positive `rootPids`, and `cacheRoots` entries `{id,path,kind}`. Optional `stageRoots` entries are `{pid,purpose}`; purpose beginning `audit` or `maintenance`, and `maintenance_owner` image names, mark audit actors and descendants. Optional `disallowedWarmRoots` are absolute local paths. Full capture evidence additionally requires `captureResultPath` and its expected `captureResultSha256`. Unknown config fields are rejected. Files/reparse boundaries are checked; ETL/config are held open without write/delete sharing. Output is create-new.

Two streaming TraceEvent passes resolve process identities/lifetimes followed by file operations. The longest matching declared cache root owns each observed path. `files` contains functional observations; `auditFiles` contains audit observations separately. Per-file counts and process-identity consumers distinguish reads, written-only, opens-only and metadata-only. `fileObjects` are hex strings. Missing names and lost events block classifications; unknown samples are bounded to 256 while total counts remain exact. Unrelated unsubscribed ETW event kinds do not imply event loss. Unexpected cache-shaped accesses and configured disallowed warm accesses are reported and block classifications pending owner review. Outside-root non-cache event totals are counted without retaining each path. Cache-shaped detection is a heuristic, not proof that every undeclared cache is found.

`decodeComplete` means both ETL passes completed, selected roots were identified, root PID identity was unambiguous, with no lost events or unresolved functional file operations. Exit 0 reflects that scope; exit 2 writes an incomplete report, while invalid input/processing exceptions return 1. `captureComplete` additionally binds a successful capture result to the ETL hash and verifies functional lifetimes between recording-ready and stop. `unusedClassificationEligible` requires all completeness checks, including observed process start and stop. It is per-run observation evidence only. A missing file row means no observed matching event; no root or absent file is globally classified unused. Output never changes deletion authority or owner protections.

Existing known-child ETL uses root PID 41832 and child 43736. The root predates recording; child reads 6,291,456 and writes 2,097,152 bytes. The broader analyzer also subscribes metadata events, and truthfully reports unresolved operations rather than turning the earlier read/write-only acceptance into full-capture completeness. Its functional unknown samples and audit unknown samples are separate, each bounded to 256, with exact per-process counts and a separate functional unknown-read/write counter. This fixture therefore returns incomplete evidence exit 2 while protecting the known-child byte assertions. `--self-test` exercises the same PID lookup and file-object close/reuse methods without output files.

## Fixed external administrative capture

Root must first register a unique capture run, create `inputs`, `outputs`, `temporary`, `logs`, `reports`, copy this helper, `ControlContract.ps1`, and the accepted `CacheIO.wprp` as immutable inputs, and supply `<runRoot>/inputs/control.json`:

```json
{"schema":1,"nonce":"<64 lowercase hexadecimal characters>","runRoot":"<absolute registered run root>","instanceName":"ET01-<16 lowercase hexadecimal characters>","maxDurationSeconds":86400,"minFreeBytes":1073741824}
```

Run `pwsh -NoProfile -File <helper>/Invoke-CacheCapture.ps1 -ManifestPath <runRoot>/inputs/control.json` only in an already-administrative external terminal. `-ValidateOnly` validates identity, fixed profile, paths and collision checks without tracing or writing files and does not require elevation. Duration is integer 60..86400 seconds; free-space floor is integer >=1GiB. Manifest stays open without write/delete sharing. A create-new claim rejects concurrent/rerun use; all result files are create-new.

Wait for `reports/armed-ready.json`, verify schema/nonce/helper PID/start identity, then atomically publish `inputs/start-request.json` with exactly `{"schema":1,"nonce":"<same nonce>","command":"start"}`. The helper runs only installed System32 WPR with the fixed profile, `-filemode`, contained `-recordtempto`, and the named instance; it records actual exit/PID/time/stdout/stderr. A successful named-instance status creates `reports/recording-ready.json`. Root must start its fresh functional producer only after verifying this recording-ready identity. The outer controller is not a functional trace root.

After the entire functional tree has terminal evidence, atomically publish `inputs/stop-request.json` with the same exact schema/nonce and `command:"stop"`. The helper stops only its named recording with `-skipPdbGen`, merging to `outputs/build.etl`. `reports/capture-result.json` contains truthful start/stop outcomes, timing, error and ETL SHA256; only successful requested stop produces `completed:true`. Watchdog disk/duration or invalid nonce/control stops its own successfully started recording and reports incomplete. No global cancel or forced process termination is used. WPR operations exceeding 600 seconds remain termination-unconfirmed with PID/start identity; external recovery is then required, without rerunning that run. The control-poll watchdog does not interrupt a running WPR operation; its fixed 600-second command bound applies instead. WPR command diagnostics are in `logs/wpr-{start,status,stop}.json`.

Process/thread and file-event capture provides observed access evidence, not content reads through every possible mechanism (for example, memory-mapped data access may not appear as ordinary FileIORead). Preserve native owner cache hit/miss/output receipts and all ownership protections when interpreting results. No live administrator capture is part of helper validation.
