# README 기초 구조와 기능 설명 분리

- 요청·권한: 한국어·영어 README의 기존 1·2장 설명을 3. 기타에 모으고 기존 Profile·Team도 보존한다. 새 1장은 Azrael의 하네스 구조로 이름 짓고 세부 설명 순서는 제안한다. 새 본문 작성은 후속 논의다.
- 합의: 포트폴리오용 간결한 어조, 두 언어 동시 수정, 기존 그림·표·본문 보존. 1·2장은 재작성용 제목을 남기며 3장의 소항목은 기존 순서로 a–k를 부여한다. 주요 기능 요약과 설치·지원 절은 이번 이동 범위 밖이다.
- 근거: docs/architecture/instructions.md의 native instruction projection·Profile composer, model-harness-profiles.md의 prompt/tool/runtime 경계. 시스템 프롬프트 조합을 먼저 설명하되 상세 구조와 작성 순서는 제안으로 구분한다.
- 범위·검증: 제품·플랫폼 동작 변경 없이 README 두 파일과 이 기록만 수정한다. Windows에서 기존 본문·그림·표 보존, 목차 앵커, 두 언어 구조 대응, git diff --check를 확인한다. 빌드·제품 테스트는 필요 없다.
- 정리: 할당 입력을 즉시 일반 삭제하고 부재 확인. 새 임시 산출물 없이 작업별 커밋한다.

## 새 1장의 구성 제안

1. 하네스 전체 흐름: 사용자 요청, 지침·도구 구성, 모델 호출, 도구 실행의 관계를 짧게 소개한다.
2. 시스템 프롬프트 조합: 공통 행동 지침·런타임 지침·사용자 및 프로젝트 지침·역할 및 프로필의 기여와 출처를 설명한다. 실제 전송의 단일 system 문자열과 논리적 지침 구성을 동일시하지 않는다.
3. 필요한 맥락의 선택적 로딩: 스킬 목록과 본문, Playbook·참조 문서의 역할을 구분한다.
4. 지침과 실행 권한 분리: 모델에 보이는 도구와 실제 런타임의 도구·승인·샌드박스 경계를 설명한다.
5. 요청별 구성 유지: 프로필 변경, 요청 스냅샷과 진행 중인 요청의 경계를 설명한다. 소스 구현과 통합 수용의 차이를 유지한다.

전체 흐름 한 문단 이후 시스템 프롬프트 조합을 첫 상세 설명으로 삼는 것을 추천한다. Profile·Team·협업·대기 등의 응용 설명은 기초 용어를 재사용하도록 후속 재작성하며 지금은 보존한다. 이 순서는 제안이며 README 본문에는 아직 추가하지 않았다.

## 결과

- 두 언어의 11개 소항목을 3장으로 모아 a–k로 재번호화했다. 1장의 이름을 바꾸고 1·2장은 재작성용 제목으로 유지했다.
- Python 메모리 검증 exit 0: 이동한 본문은 소항목 문자 외에 동일하며 표·그림·문단이 보존된다. 문서 앞부분과 플랫폼 지원 이후 내용도 보존했다. 각 언어의 목차 앵커 20개가 유효하다. `git diff --check` exit 0.
- 임시 계획 입력의 일반 삭제와 부재를 확인했다. 새 제품 코드·테스트·임시 산출물은 없다. 이번 검증은 Windows에서 문서 구조와 보존을 확인한 범위다.
