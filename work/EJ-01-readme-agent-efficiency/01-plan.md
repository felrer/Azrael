# README: 에이전트의 효율화

## 목표와 범위

- README.ko.md와 README.md의 첫 주제를 포트폴리오용으로 보강한다. 짧은 문장으로 docs 체계, 자체 스킬, root/subagent 지침·소통, defer_root를 설명한다.
- 요청된 두 대주제는 에이전트의 효율화 / 사람의 인지 부하를 줄이기다. 이번에는 첫 주제만 집필하고 뒤의 기존 기능 설명은 보존한다.
- 기존 소통 방식 표를 그대로 활용한다. 역할 분담과 대기·재개는 언어별 Mermaid로 작성하고 외부 작업의 종료 플래그 경로를 포함한다. lead는 후속 구현으로 표시한다.
- work.md 중복은 한 번으로 정리하며 실제 스킬 이름 implementation을 사용한다. 기능·공유 지침·아키텍처 계약 변경은 없다.
- 공통 문서 변경이며 지원 OS·CPU·ABI·로컬/원격 지원 범위를 바꾸지 않는다. 실제 검증은 Windows 작업공간의 문서 정합성에 한정하며 제품 실행 검증으로 확대 해석하지 않는다.

## 근거와 실행

- docs/README.md, docs/playbooks/work.md, docs/architecture/multi-platform.md와 설치된 development-workflow, implementation, testing 지침을 적용한다.
- docs/playbooks/README.md 및 자체 스킬 원문을 바탕으로 구성한다. 설계 상태와 구현 상태를 분리하고 측정되지 않은 성능 개선을 단정하지 않는다.
- root가 README와 이미지 출처 문서의 필요한 설명, 이 작업 기록을 소유한다. 읽기 전용 readme_contracts 에이전트는 협업·재개 계약의 근거를 확인한다. 공유 작업공간의 기존 변경을 보존한다.
- 조사 결과를 받은 뒤 root가 양 언어를 함께 작성하고 링크·언어 대응·도식·변경 범위를 확인한다. 소스나 실행 계약을 바꾸지 않아 아키텍처/feature inventory 변경은 필요 없다.

## 성공 기준과 검증

- 네 docs 범주와 기본 playbook 세 종류, 자체 스킬의 특징을 설명한다.
- root의 설계·스케줄링 책임과 subagent의 범위·근거 중심 실행, 후속 lead를 구분한다.
- 기존 세 가지 소통 방식 표를 유지하고 defer_root의 선택 대상 모두 종료 조건, 외부 종료 플래그, 예약 시각과 수동 재개를 설명한다.
- 두 언어의 핵심 내용과 그래프가 대응하고 로컬 링크 및 Mermaid 구문이 유효하다. 기존 후반 본문이 보존되어야 한다.
- 불필요한 테스트 파일·빌드·설치 없이 최소 문서 검증을 수행한다. 임시 자료는 사용 후 제거하고 실제 부재를 확인한다. 작업별 커밋은 이 작업 파일만 포함한다.

## 산출물과 정리

- 유지할 산출물: README.md, README.ko.md, 필요한 docs/images/README.md 출처 설명, 이 작업 계획 및 간단한 검증 결과.
- 할당 도구 입력 work/.readme-agent-efficiency-plan-body.md는 이 작업 소유 임시 문서다. 새 계획 생성 직후 일반 삭제하고 부재를 확인한다.
- 추가 임시 검증 산출물이 필요하면 생성 전에 이 기록에 경로와 정리 시점을 기록한다.
- 도식 검증은 기존 artifacts/upstream-ui/26.1007.21434/webview/assets/mermaid.core-2bb0614a5c95.js를 읽기 전용으로 사용한다. 이 작업의 루프백 HTTP 서버는 README의 도식과 기존 JS 자산만 메모리에서 제공한다. 파일·프로필·로그를 생성하지 않으며, 검증 후 생성한 브라우저 탭과 서버를 종료한다. 스크린샷은 도구 응답으로만 확인한다.

## 결과

- README 두 언어를 문서 체계 → 자체 스킬 → root/subagent 역할·소통 → 대기·재개 순서로 정리했다. lead는 후속 구현으로 표시했다.
- 각 README에 역할 분담과 재개 흐름 Mermaid를 별도로 작성했다. 외부 작업의 work_completion 종료 플래그, all_terminal, 예약 시각·직접 재개, request_parent 경로를 포함했다.
- 두 번째 대주제의 제목·하위 제목 계층만 정렬했다. 소통 방식 표는 원문 그대로, 두 번째 대주제 이후 본문은 제목 변경 외에 그대로 유지했다. docs/images/README.md의 도식 출처 설명을 맞췄다.
- Windows 문서 검사: Python 3.12의 일회성 메모리 검사 종료 코드 0. 각 언어의 로컬 링크·앵커 34개, Mermaid 블록 2개, 기존 표·후반 본문 보존을 확인했다. 양 언어의 참조 목록과 그래프 구조도 일치한다.
- 기존 Mermaid 렌더러와 연결된 Chrome에서 네 도식의 파싱·렌더링 및 화면 배치를 확인했다. 각 언어에서 역할 도식은 5개 노드/4개 연결, 재개 도식은 6개 노드/9개 연결이다. GitHub 실제 호스팅 렌더링이나 제품 동작을 검증한 결과는 아니다.
- 전체 페이지 캡처가 시간 초과되어 지원되는 접근성 화면 캡처로 확인했다. 캡처 파일·검증 스크립트·브라우저 프로필은 생성하지 않았다.
- 임시 계획 입력 파일의 일반 삭제와 실제 부재를 확인했다. 검증 탭을 닫고, 미리보기 서버를 정상 종료했다(exec session 39385, exit 0). 추가 정리 대기 항목은 없다.
- 빌드·설치·제품 테스트는 실행하지 않았다. 실행 계약과 플랫폼 지원 범위는 바뀌지 않는다. 상세 도구 출력 대신 위의 최소 검증 근거를 이 기록에 유지한다.
