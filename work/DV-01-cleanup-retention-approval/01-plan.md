# 작업 종료 시 정리 의무와 보존 승인

- 목표: 필요가 끝난 작업용 생성물을 즉시 정리하고, 남기려면 사용자의 명시적 허락을 받도록 지침을 일치시킨다.
- 범위: 공통 지침, implementation과 관련 참조, bootstrap 수명주기 예제, 프로젝트 Work/Build/수명주기 규칙, 배포 해시, 활성 설치본. 기존 산출물 삭제와 앱 런타임 변경은 제외한다.
- 플랫폼: 모든 지원·의도 플랫폼에 공통인 작업 규칙이다. Windows에서 문서·배포 매핑·활성 설치본 일치를 검증한다. 앱 빌드 및 타 OS 실행은 대상이 아니다.
- 결정: 성공·실패·취소 모두 필요가 끝난 생성물은 즉시 정리한다. 보존에는 경로, 필요성, 확인 가능한 용량, 해제/재검토 조건과 사용자 명시적 승인이 필요하다. 범위·조건이 유효한 기존 승인은 재사용한다. 응답 전 보류는 미해결이며 작업 완료로 보고하지 않는다.
- 보호: 사용자 자료·소스·현재 설치·실행 참조·미확인 소유권은 삭제하지 않는다. 보호 사유만으로 보존 승인이 생기지 않는다. 삭제 불가 시 보존 승인을 요청하며 강제 삭제와 잠금 우회는 금지한다.
- 순서: 소유 지침/관련 예제 수정 → 프로젝트 규칙 정합화 → 배포 해시와 활성 복사본 반영 → 기존 검사 및 diff 검토 → 임시 파일 제거 및 작업 단위 커밋.
- 완료 조건: 실제 정리 완료 또는 사용자 보존 승인 없이는 완료 선언 불가. 결과 기록만으로 정리 완료를 대체할 수 없다.
- 검증: maintained library, 공통 지침 검사, 활성 파일 일치, diff와 사례 검토. 실제 후속 대화 준수나 런타임 차단을 검증했다고 주장하지 않는다.
