# 전용 테스트 정리 playbook

## 요구와 권한

- 앞선 테스트 생성 필요성 지침과 일관된 `docs/playbooks/test-cleanup.md`를 새로 만든다. 현재 별도 문서는 없고 Work의 테스트 묶음 절과 artifact lifecycle에 관련 규칙이 나뉘어 있다.
- 산출물은 전용 playbook, playbooks 목차와 Work의 연결, 이 작업 기록이다. 이번 요청은 문서 작성이며 실제 테스트·fixture·runner 설정 삭제나 제품 코드 변경은 포함하지 않는다.
- 공통 정책은 Windows·Linux·macOS에 적용하며 이번 문서 검증은 Windows x64에서 수행한다. 기존 필수 검증·플랫폼 보존·생성물 관리·정리 및 보관 승인 규칙을 유지한다.

## 설계와 실행

- 루트가 직접 작성한다. 범위가 작은 문서 작업으로 위임·작업 트리·새 테스트는 필요하지 않다.
- 계약과 고유한 회귀 탐지 가치, 중복의 실제 경계와 입력·환경, 유지/통합/이동·수정/폐기/보류를 구별한다. 개수·커버리지 목표나 일률 삭제 금지는 사용하지 않는다.
- 유지 중인 테스트 소스와 생성물을 분리하고, 원본 테스트의 실패·skip·플랫폼 조건·고위험 계약을 조사 없이 폐기하지 않는다. 대체 검증의 실제 assertions, 실행 경로와 비어 있지 않은 실행 결과로 보존을 확인한다.
- 기존 implementation §7/§8, 기능 보존, 프로젝트 관리 운영 및 artifact lifecycle 소유자를 연결한다. 별도 승인 단계·심사표·runner·일괄 mutation 캠페인은 추가하지 않는다.
- 프로젝트 playbook을 추가할 뿐 instruction 배포·bootstrap 기본 구성·제품 동작은 바꾸지 않아 별도 아키텍처·공통 skill 변경은 없다.

## 검증과 정리

- 변경 문서와 링크 대상·앵커를 확인하고 `git diff --check` 및 기존 지침과의 의미 대조를 수행한다. 새 문서의 존재·문구만 확인하는 테스트는 만들지 않는다.
- 삭제 할당량 없음, 중복 동작의 보존, 중요한 정적 계약과 조건부 플랫폼 테스트 보호, zero-test 성공 오판 방지, 실제 삭제 권한과 문서 작성 권한 구분을 검토한다.
- 임시 계획 입력은 배정 직후 일반 삭제하고 부재를 확인한다. 실제 테스트 정리·생성·실행은 하지 않으며 이 계획은 유지되는 요구·검증 기록이다.
- 기존 staged/unstaged 변경은 보존하고 이 작업 파일만 명시적으로 커밋한다. 원격 push·빌드·설치는 범위 밖이다.

## 결과

- `docs/playbooks/test-cleanup.md`를 작성하고 `docs/playbooks/README.md` 및 `docs/playbooks/work.md`에 적용 경로를 연결했다.
- 유지·통합·수정/이동·폐기·중복 제거·보류의 기준, 고유한 반복 탐지 가치와 실행/진단/리뷰/유지비용 비교, 대체 검증의 계약·입력·경계·플랫폼 조건 보존을 담았다. 삭제 0건도 허용하며 수치 할당량은 두지 않았다.
- 정적 값·직렬화·보안 allowlist·생성물이 실제 계약일 수 있다는 예외, 조건부 skip/실패 조사, 실제 제품 연결과 비어 있지 않은 테스트 실행 확인, 보존해야 할 필수 검사와 플랫폼 계약을 대조했다. 제품 결함을 가리는 삭제나 임시 확인의 불필요한 영구화를 허용하지 않는다.
- Windows x64에서 새 문서의 모든 로컬 링크와 두 진입점의 새 링크를 인라인 문서 검사로 확인했다: 12개 링크/앵커, exit 0. 재사용 가능한 문서 링크 검사 전용 도구가 없어 파일을 남기지 않는 읽기 전용 확인을 사용했다.
- `git diff --check`를 통과했다(exit 0). 지침 내용의 의미 대조와 링크 검증이며 실제 테스트 정리 결과나 모델 행동 개선을 검증한 것은 아니다. 제품·runner·테스트 소스는 변경하지 않아 제품 빌드와 회귀 실행을 추가하지 않았다.
- `work/.test-cleanup-plan-input-20261027-b27e3.md`는 계획 배정 직후 일반 삭제하고 부재를 확인했다. 새 테스트/검증 스크립트/별도 로그/빌드 산출물을 남기지 않았다. 이 계획은 유지되는 작업·검증 기록이며 정리 대기 항목은 없다.
- 이번 네 파일만 명시적으로 선택해 커밋한다. 기존 staged/unstaged 작업과 공통 instruction 배포 구성은 바꾸지 않는다. 커밋 식별자는 최종 보고에서 제공한다.
