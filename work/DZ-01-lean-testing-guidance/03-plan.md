# testing 스킬 초안

## 요구와 권한

- 사용자는 `testing` 스킬을 먼저 만들고 내용을 한국어로 직역해 제시하도록 요청했다. 공통 테스트 기준을 분리한다는 방향은 합의되었다.
- 산출물은 이 세션의 `testing/SKILL.md`와 검토용 `testing-ko.md`다. 이번에는 배포 라이브러리·활성 설치·implementation·Build·테스트 정리 playbook을 변경하지 않는다. 검토 후 공통 기준의 소유권과 참조를 함께 옮길 수 있도록 독립된 스킬 형식으로 작성한다.
- 공통 정책은 플랫폼에 독립적이다. 이번 검증은 Windows x64의 문서·스킬 형식 검증이며 실제 모델 행동이나 제품 회귀 검증을 주장하지 않는다.

## 설계와 실행

- 기존 implementation §7 및 테스트 정리 playbook의 합의된 기준을 재사용한다. 기존 증거 우선, 신규 테스트 추가의 선택성, 장기 보호 가치와 비용, 실제 경계와 독립적인 기대값, 실행 결과 재사용과 한계, 계약 기반 정리를 포함한다.
- 테스트 지침은 테스트 선택·작성·실행·유지·통합·폐기를 소유한다. 작업 범위·승인·전체 완료·생성물 수명주기, 고정 빌드 입력·캐시·패키징·설치와 프로젝트별 필수 명령은 기존 소유자에게 둔다.
- 삭제 0건 허용 문구나 무조건 전체 삭제 허용을 추가하지 않는다. 테스트 수를 할당량으로 사용하지 않으며 필수 계약과 검증을 유지한다.
- 루트가 직접 작성한다. 영어 원문과 동일 순서·의미의 한국어 직역본을 검토 산출물로 유지한다. 영문 스킬을 나중에 정식 위치로 옮기기 전까지 자동 활성화하지 않는다.

## 수락 기준과 검증

- 실제 `SKILL.md`를 만들고 skill-creator의 기존 quick_validate로 형식을 검증한다. 영어와 한국어 내용을 대조하고 `git diff --check`로 공백 오류를 확인한다.
- 문서 작업을 위해 별도 테스트·제품 빌드·검증 스크립트는 만들지 않는다. 형식 통과와 모델 행동 효과를 구분한다.
- 임시 계획 입력 파일을 배정 직후 일반 삭제하고 부재를 확인한다. 초안·직역본·계획은 요청한 검토 산출물로 유지하며 일회용 파일이 아니다.
- 기존 동시 작업과 staged 변경을 보존하고 이 작업의 세 파일만 명시적으로 커밋한다. 원격 push는 하지 않는다.

## 결과

- [영어 스킬 초안](testing/SKILL.md)과 [한국어 직역본](testing-ko.md)을 작성했다. 범위와 소유권, 최소한의 충분한 증거, 지속적으로 유지할 테스트, 실행과 재사용, 기존 테스트 정리, 보고와 종료의 여섯 절이다.
- skill-creator의 기존 `quick_validate.py`가 Windows x64에서 종료 코드 0으로 `Skill is valid!`를 반환했다. 영어와 한국어의 순서·규칙·예외를 대조했다. 이는 형식과 문서 일관성 확인이며 실제 모델의 테스트 생성·정리 행동이 개선되었다는 증거는 아니다.
- 새 테스트나 검증 스크립트·제품 빌드·실행 로그 파일을 만들지 않았다. 계획 배정 입력 `work/.testing-skill-plan-input-20261027.md`는 일반 삭제했고 `Test-Path`가 `False`를 반환했다. 정리 대기 중인 일회용 자료가 없다.
- 세 파일의 staged 변경에 `git diff --cached --check`를 적용한 뒤 이 세 경로만 선택해 커밋한다. 기존 네 개의 staged 소스 파일은 커밋에서 제외하고 그대로 보존한다. 커밋 식별자는 최종 보고에 제시한다.
- 스킬은 검토 산출물로 `work/`에 있으며 자동 활성화하지 않았다. 검토 후 정식 `instructions/skills/testing/` 배치, 활성 설치와 배포 메타데이터 동기화, 기존 문서의 공통 기준 이전 및 참조 변경이 후속 작업이다.
