# 테스트 생성 필요성 판단 보완

## 목표와 범위

- 사용자가 승인한 lean-testing의 명확한 생성 전 판단 기준을 기존 `implementation`의 검증·테스트 관리 절에 통합한다.
- 새 테스트 0개 허용, 기존 검증 우선, 영구 테스트의 공백·반복 탐지 가치·총비용 판단, 임시 확인의 자동 영구화 방지, mock/helper 증식 재검토, 실제 실행 불가 시 공백 보고, 수치 목표 금지를 포함한다.
- 기존 필수 검증, 중요 계약 보호, 플랫폼 회귀, 실패 처리, 정리·보관 승인 규칙은 유지한다. 외부 스킬 설치, 제품 빌드·배포, 기존 테스트 삭제는 범위 밖이다.
- 공통 정책으로 Windows·Linux·macOS에 적용한다. 이번 실제 검증 환경은 Windows x64이며 제품/모델 행동 개선의 실측을 주장하지 않는다.

- 저장소에 다수의 기존 변경과 staged 항목이 있으므로 이 작업 파일만 명시적으로 선택해 커밋한다.

## 실행과 검증

1. 소유 절의 기존 최소 검증 문장을 확장하고 생성 전 판단·영구화·과잉 생성 제한을 통합한다.
2. 예시·현재 파일 기록을 갱신하고 원본과 활성 설치본을 동기화한다.
3. 기존 `quick_validate.py`와 `import-instructions.py --check`로 스킬 형식, 참조, 현재 해시와 배포 매핑을 검증하고 `git diff --check`와 원본/설치본 동일성을 확인한다.
4. 승인된 각 기준 및 중요한 보존 계약을 문서 대조한다. 지침 문구 검증과 실제 에이전트 행동 검증은 구별한다. 새 테스트 파일은 만들지 않는다.
5. 일회성 계획 입력을 즉시 삭제하고 실제 부재를 확인한다. 유지할 작업 계획은 요구·검증 기록으로 관리한다. 작업 변경만 커밋한다.
