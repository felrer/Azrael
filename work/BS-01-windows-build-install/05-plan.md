# Windows 2026.0.9 빌드와 설치

사용자가 지금까지 추가된 모든 기능을 반영한 Windows 2026.0.9 빌드와 일반 VS Code 사용자 프로필 설치를 명시적으로 요청했다. 현재 선택한 tracked/untracked/deleted 소스와 스크립트를 고정하고 이후 primary 변경은 포함하지 않는다. 기존 상태·계정·대화·일반 Codex를 보존한다. 원격 게시·사용자 창 종료·자동 reload·Windows 서비스/UAC 설정 변경은 범위 밖이다.

## 진행과 검증

root가 입력 고정, 빌드, 통합, 설치, 정리를 소유한다. Windows x64/MSVC만 검증하며 Linux/macOS 수용으로 확대하지 않는다. 버전은 2026.0.9로 변경한다. Window Use의 실제 자식 세션 연결/앱 입력 수용은 이번 패키지 설치의 성공과 별도이며 미확인 상태를 보존한다.

범위가 넓고 설치본 이후 engine/host/provider/Window Use 변경이 있어 전체 current/standalone 소스와 등록된 engine/UI 검사를 선택한다. 기존 조건부 expensive tool matrix 정책과 유효한 동일 입력 cache receipt를 보존하며, 모든 최종 host 6단계를 새 상태로 실행한다. 엔진/bridge는 같은 입력으로 생성하고 code-mode host는 명시 SHA를 기록한 호환 외부 import를 사용한다. 기본 4개 source concurrency 대신 현재 여유 메모리를 고려해 2개로 시작하며 Cargo jobs도 2개로 제한한다.

긴 기본 fixture 상태 경로의 Windows AF_UNIX 한계를 피하기 위해 기존 개별 build/prepare/check/install owner를 호출하고 짧은 새 상태를 선택한다. 필수 검사와 exact package identity 확인을 생략하지 않는다. source/build 성공 뒤 package preparation과 engine verification을 가능한 범위에서 병행한다. 입력, 실제 exit, package SHA/버전, 설치 receipt, 원본 확장·설정 보존을 확인하고 소유 disposable/오래된 비보호 버전을 정리한다. 실패하면 원인 경계의 최소 재현부터 고친 뒤 새 입력 identity로 다시 생성한다.

입력 snapshot: artifacts/n9a. root 실행 로그: artifacts/tasks/windows-2026-0-9/runs/w09a. build release identity: w09a. 제품 artifacts는 frozen project 아래의 releases/logs/deployments 소유 경로를 사용한다. 이전 설치/rollback/실행 중 runtime은 보호한다.
