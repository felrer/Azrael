# Windows 2026.0.10 빌드 및 사용자 프로필 설치

상태: 입력 고정 준비 중. 사용자 승인: 현재 변경 전부를 포함해 2026.0.10 빌드 및 일반 VS Code 사용자 프로필에 설치.

범위: Windows x64/MSVC, engine/ 실제 소스 및 미커밋 provider/model 변경 포함. 공통 변경의 기존 의미를 보존하고 Linux/macOS 실제 실행 검증은 이번 범위 밖이다. 기존 사용자 데이터·계정·설정과 실행 중 창/엔진을 보존한다. 현재 실제 등록은 2026.0.8/w31b이며 2026.0.9/w09h-r2도 복구 근거로 보존한다.

절차: 릴리스 버전 변경 후 전체 선택 입력을 독립 Git metadata를 지닌 artifacts/n10a에 고정한다. 외부 UI/runtime/호스트와 실제 도구·캐시 경로/해시를 고정하고 소유 생성물 lifecycle을 먼저 기록한다. Windows PTY 사전 검사 후 같은 Cargo target에서 엔진+브리지를 새로 빌드한다. 코드 실행 보조 호스트는 명시한 검증 파일을 import한다(V8 source build 제외). 공유 Cargo producer는 하나만 실행한다. 엔진 namespace/storage/thread 계약과 provider-context 변경을 포함한 광역 계약 변경이므로 FullRegression을 선택하고 검증된 cache receipt만 재사용한다. 최종 패키지의 여섯 fresh-state host 단계, package identity, 보존 및 설치 receipt를 확인한다. 검사와 빌드의 실제 exit/시각/로그를 기록한다.

기존 protocol1 엔진이 실행 중이므로 최초 protocol2 적용은 모든 VS Code 창의 정상 종료 후 재실행이 필요하다. 이번 설치 과정이 사용자 창을 강제 종료하거나 저장 데이터를 변경하지 않는다. 설치와 실제 새 엔진 활성화를 구분한다. 후속 protocol2 릴리스는 버전별로 공존한다.

완료 조건: 2026.0.10 최종 패키지 검증·사용자 프로필 등록 및 실제 설치 파일 identity 확인, 실행 창 전환 필요 여부 명시, 현재/직전 복구·실행 참조 보호와 생성물 정리 결정, owning current state/본 기록 갱신 및 작업별 commit. 이 작업 이전 BW-01 변경은 빌드에 포함하되 해당 작업의 변경 소유권을 임의 커밋하지 않는다.

일정: root가 입력/빌드/통합/설치 소유, read-only preflight 담당이 ignored/external dependency 경로를 확인한다. 입력 고정과 외부 준비가 빌드의 선행 조건이다. 빌드 후 source/engine/preparation 결과를 최종 host 검증이 소비한다. 준비 컴파일과 실제 검사 시간을 구분하고 overlap을 합산하지 않는다.
