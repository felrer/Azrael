# 상태: 최신 커밋 Windows 빌드 준비 중; 사용자 추가 응답 불필요

## 목표와 권한

요청 시점 커밋 `407c7d439beee6f2660c21ed4344147370c20967`을 고정해 Windows x64 최신 배포를 빌드하고, 실제 소요 시간과 병목으로 후속 개선을 분석한다. 미커밋 기능 변경과 이후 커밋은 제외한다. 이번 요청은 빌드이며 사용자 설치·원격 게시·추가 기능 개편은 하지 않는다. 터미널은 숨겨 실행한다.

## 준비·실행·검증

기존 lifecycle, deployment-workspace, deploy-azrael의 VerifyOnly 경로와 캐시 소유자를 사용한다. 소스 선택과 검사 범위를 구분하고 실제 변경 owner와 mandatory gate를 유지한다. 별도 커밋 checkout에서 입력을 준비하고 immutable 입력 및 별도 실행 workspace를 만든다. 기존 소비자와 동시 Cargo target, 용량, 설치된 도구·runtime·UI를 고정한다. Windows PTY native preflight를 먼저 통과시킨 뒤 제품 빌드와 준비된 독립 source 검사를 시작한다. 해당 native 보존 검사, 패키지 준비와 fresh host 검증, 마지막 고정 입력·패키지 identity 검사를 완료한다. 실패/미확인 실행을 재사용하지 않는다.

## 후속 개선 분석의 현재 근거

최종 빌드가 완료되면 아래 근거에 제품 컴파일·검증·패키징의 실제 시간을 합쳐 분석한다. 아직 측정하지 않은 전체 속도 개선율은 제시하지 않는다.

1. **Cargo target의 작업 간 대기와 예약**: 한 시점에 lease가 없다는 관찰만으로, 긴 preflight 이후의 캐시 가용성을 보장할 수 없다. 이번 실행은 약18분의 관찰 대기 후에도 다른 작업의 새 lease 때문에 제품 compile 진입에서 다시 차단됐다. 기존 소유권 검사를 유지하면서 실제 compile 시작 지점에서 bounded queue/wait를 지원하는 개선이 우선 후보이다. 다른 작업을 중지하거나 lease를 제거하는 해결은 포함하지 않는다.
2. **freeze 전에 정합성·실행 환경을 일괄 확인**: `cargo metadata --locked --offline`, recipe/audited-helper, lock 기반 TypeScript 준비, 실제 PowerShell의 단일 Node 해석, fixture 경로의 형식과 UTF-8 socket byte 수를 기존 preflight의 같은 입력 계약으로 확인해야 한다. R1 freeze 20분31초를 끝낸 뒤 3초 만에 lock 오류가 드러났다. PATH 및 재시도 fixture 준비 실수는 root의 작업 helper에서 발생했으므로 제품 결함과 구분한다.
3. **불변 입력과 출처 증거의 재사용**: R2 생성18분34초와 handoff 비교2분43초가 실측됐다. SOURCE 원본·receipt가 동일한 반복 실행에서는 content-addressed input과 증거 재사용을 검토할 수 있다. source/parent identity 및 최종 package 검사는 유지해야 하며 단순 Git HEAD 일치로 대체할 수 없다.
4. **검증 fixture의 단일 목록**: 기존 readiness 목록에 manifest validator와 packaging test가 실제 읽는 UI 파일이 빠져 있었다. 필요한 파일은 최종12개인데 초기 전체 UI 복사 시도는 불필요하게 약1GB의 부분 복사를 만들었다. 테스트의 직접 파일 읽기까지 owner가 선언하고, helper가 그 목록만 준비하도록 연결하는 개선이 필요하다.
5. **정리 제어 경계와 관찰 비용**: immutable/workspace producer의 complete membership과 기존 capture hash가 있어도 최초 native 등록에서 payload 확인 비용이 다시 발생한다. 이번 R1 working group의 등록은 약4분40초였고 반복된 source 경로별 owner 정보 때문에 review 출력도 커졌다. 검사 생략을 전제로 하지 않고, native 측에서 group 단위 공유 검사를 중복 수행하는지 계측하고 요약 출력/단계별 진행 신호를 검토한다. 현재 구현의 내부 중복 여부는 아직 확정하지 않았다.
