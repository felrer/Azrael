# Azrael 전용 VS Code 프로필 정리

- 요청·권한: `%LOCALAPPDATA%/azrael-ex/vscode` 미사용 파일 조사와 안전한 정리. 사용자 지정 경로 확정.
- 플랫폼: Windows x64 로컬 프로필만 대상. 제품 코드·지원 플랫폼 변경 없음.
- 보존: 설정, 대화, 인증, 편집 기록, 미저장 백업 및 실제 설치·복구·실행 참조. 프로필 전체 폐기는 승인 범위 아님.
- 절차: 기존 관리 기록과 실행·shortcut 참조 확인 → 생성물과 사용자 데이터 분리 → 검증된 maintenance_owner로 외부 관리 루트 등록·심사·삭제 → 부재·보존 확인.
- 소유: root 단독 수행. 산출물은 이 작업 기록과 최소 정리 영수증. 제품 구현 변경이 없으므로 아키텍처 변경·제품 빌드 불필요.
- 성공 기준: 삭제 항목별 소유·미사용 근거, 실제 삭제 결과·회수량, 보존 범위와 불확실성 기록.
- 현재 근거: 구버전 확장 설치본 2개와 user-data 존재. current.json은 20260913-142824-614 참조. 실행 중 Code의 user-data는 일반 Roaming/Code. 실제 엔진에는 2026.0.13 경로가 있어 과거 설치 문서만으로 미사용 판정하지 않음.

## 확정 범위와 실행

- 전체 메타데이터 조사: 오류·링크 없음. 두 설치본은 각각 약 2.17GB로, 실행용 `extensions`와 설치 준비용 `staging`이 함께 남아 있다. 최소 조사 결과는 `03-inventory.json`에 보존했다.
- 현재 포인터는 두 번째 설치본을, 두 번째 설치본의 복구용 `previous-azrael-shortcut.lnk`는 첫 번째 설치본의 `installation.json`을 참조한다. 실행용 확장 두 개와 설치·복구 제어 파일은 지속 설치 소유로 보존한다. 이번 작업의 임시 산출물이 아니다.
- 삭제 후보: 두 `staging` 디렉터리, `user-data`의 Cache/CachedConfigurations/CachedData/CachedProfilesData/Code Cache/DawnGraphiteCache/DawnWebGPUCache/GPUCache/logs, 총 11개 경로.
- 197개 바로가기·실행 스크립트에서 프로필 절대 경로 참조 없음. 바탕화면은 직접 파일, 시작 메뉴와 Quick Launch는 재귀 조사. 임의의 다른 디렉터리나 모든 상대·간접 참조까지 증명한 것은 아니다.
- 프로필 경로를 참조하는 실행 프로세스 없음. 초기 바로가기 조회 2회는 바탕화면 재귀 탐색 지연으로 중단(exit1)했으며 범위를 좁힌 조회는 exit0이다.
- 관리 실행기는 설치 selector의 SHA256과 일치한다. 외부 프로필에 독립 `project-maintenance.json` 및 보호 경로를 설정하고 inventory에서 기존 등록 그룹이 없음을 확인했다. 등록은 `eo01-isolated-profile-disposable` 전체 묶음으로 진행한다.
- 보존 경로: 사용자 데이터·설정·인증·편집 기록·미저장 백업, 양쪽 설치의 extensions와 메타데이터, current.json. 관리 설정·최소 소유/삭제 영수증은 이 프로필의 지속 관리 제어 자료다.
- 검증 선택: 제품 변경이 없으므로 제품 테스트·빌드는 수행하지 않는다. testing의 최소 증거 원칙에 따라 실제 native 심사·삭제 결과, 삭제 대상 부재, User/Backups 등 사용자 상태와 설치 메타데이터 해시 보존을 확인한다.
- 도구 준비에서 `python` PATH 부재를 확인했으며 설치된 Python313 절대 경로로 작업 문서 배치를 완료했다. 임시 본문 파일은 삭제·부재 확인 완료. 별도 일회성 스크립트 파일은 만들지 않았다.

## 최종 결과

- native 등록·심사·삭제 실제 종료 코드 모두 0. 그룹은 `deleted`, 11개 항목 모두 `deleted/remaining=false`, 오류·취소 없음. 별도 실제 경로 확인도 11개 모두 부재. 재실행 없음.
- 삭제 논리 용량: **2,125,672,432바이트 = 약 2.13GB / 1.98GiB**. 파일시스템의 실제 할당 공간 증가량은 별도로 측정하지 않았다.
- 사용자 보호 묶음 7개(User/Backups/Local Storage/Session Storage/Network/blob_storage/current.json)의 파일 수·내용 해시와 설치·복구 메타데이터 7개 파일의 SHA256이 모두 일치한다. 실행용 확장은 삭제 대상으로 선택하지 않았다.
- 실행용 확장 2,238,430,848바이트, 사용자 상태 및 복구용 바로가기는 원래 지속 설치 소유로 보존한다. 이는 이번 작업의 정리 미완료나 임시 보류가 아니다. 참조가 해제되는 별도 프로필 폐기 시 재검토한다.
- 프로필 안 `project-maintenance.json`, `artifacts/maintenance`는 후속 소유·보호·삭제 판단을 위한 지속 관리 제어 자료이며 최소 영수증을 포함한다. 작업 기록의 JSON에는 사용자 데이터 원문이 없다.
- 일회성 `.eo01-request.json`은 작업 생성자가 최종 요청 identity를 확인한 후 ordinary unlink로 삭제하고 부재를 확인했다. 임시 본문 파일도 없다. 정리 대상 잔여·복구 대기·사용자 확인 대기는 없다.
- 최초 등록·내용 측정은 약 271초, 실제 삭제는 약 244초가 걸렸다. 보호 경계 및 파일별 일반 삭제를 유지했고 중복 실행·강제 삭제·권한 변경은 하지 않았다.
- 검증의 한계: 앱 실행·실제 계정 동작 확인은 하지 않았다. 현재 사용하는 일반 VS Code 프로필과 `.azrael-ex`는 수정하지 않았다. 전체 디스크나 임의의 간접 참조를 전수 조사했다는 의미는 아니다.
- 핵심 결과: [삭제 결과](08-apply.json), [최종 검증](09-verification.json). 각 단계의 최소 영수증을 같은 작업 기록에 보존했다.
