## Design settings

Status: `current` in source — custom photo sets and single-photo random preview verified on Windows with host tests and native light/dark rendering; packaging, installed-profile and Linux/macOS acceptance pending.

Presentation acceptance uses the production component and pinned native modules/styles with a synthetic host in light and dark themes. Source tests and browser fixtures do not establish packaged or installed-profile acceptance.

The Design page has a native **Use custom photos for new subagents** settings row. Its switch defaults to off for unset preferences and persists changes through the host-owned photo service. Turning it on affects future authoritative subagent creation events; previous photo assignments and recorded off decisions remain stable when toggling or reopening the page.

The chat and input font row uses the native segmented control to select `OpenAI default` or `Gyeonggi + monospace` together for message text and the composer. Unset and existing preferences default to `gyeonggi-consolas`; `openai` restores the pinned UI's native content, composer and code typography and normal word spacing. The host stores `chatFont` alongside student preferences, serializes changes and broadcasts confirmed snapshots to open webviews. Failed saves retain the previous font and expose the existing retry/error state. Native bridge initialization subscribes even when no settings page or subagent avatar renders, so reopening a chat restores its saved font. Other dynamic labels retain their existing typography.

The host observes `item/completed` notifications for both `subAgentActivity` with `kind: started` (v2 creation) and successful `collabAgentToolCall` with `tool: spawnAgent`. Both paths use the same per-thread saved decision, so duplicate notifications do not redraw a photo. Later activity and history reads do not allocate photos.

The Photo preview section selects the persisted image set through the pinned native dropdown menu and radio items. Its trigger displays the confirmed set name and a chevron; opening the menu lists Students, Scientists and all imported sets, marks the current selection, and supports native keyboard navigation. The selector is disabled while loading or saving. The section then shows one randomly selected photo and its display name, with a button to draw another. Students is the bundled default set, containing 200 distinct student/costume IDs: the original 100 base portraits and 100 additional portraits (44 base appearances and 56 costume variants). Existing numeric IDs and saved assignments are retained. The bundled 200 portraits use user-approved 512×512 PNG derivatives of the approved generated artwork, preserving transparency and the complete square framing. The recommended profile-image resolution is 512×512; other image dimensions remain supported for bundled and imported sets. This recommendation does not add a runtime size restriction or automatically resize imported images. The Scientists builtin uses the display name **???** in Korean locales and **Scientists** in English, in both the selected trigger and menu; stored set identity and user-defined set names do not change with locale. Scientists is an additional bundled set of 150 user-approved scientist/researcher risograph illustrations, stored as 256?256 quality-90 JPEGs with namespaced `scientists:<slug>` IDs, English/Korean names and source/output SHA-256 provenance. Adding this set does not switch existing or unset preferences away from Students, enable photos or rewrite prior assignments. Host initialization validates its roster and uses either integrated `webview/assets/azrael-scientists` or source `media/scientist-avatars` resources. Packaging validates dimensions, JPEG signatures and hashes and copies its JPEG bytes unchanged. Resize provenance records source/output hashes; packaging copies the optimized student PNG bytes unchanged. Replacement artwork still requires user confirmation and updated hashes/provenance. Displayed names distinguish costumes. Roster validation checks nonempty records, unique IDs, complete identity fields, safe filenames and PNG integrity. Selecting a set changes future subagent assignments and the preview; existing assignments, including saved off decisions, remain stable. Each side of the photo box is one third of the native `size-20` box, using the same spacing token; image alternative text also uses the English name. Preview is available while the switch is off and does not change saved preferences or subagent assignments. Loading, save failure and unavailable-photo states remain visible and accessible. Images use bundled assets or copied user assets through local webview resource URLs.

**Add image set** opens a native multi-file chooser and a set-name prompt. PNG, JPEG, WebP and GIF imports allow up to 200 regular raster files, 1 MiB each and 20 MiB total. The host checks format signatures and stores copies beneath extension global storage `subagent-photos/<set-id>/`, so source files can be moved after import. File stems supply display names. Successful import persists metadata and selects the new set. Cancellation and validation/storage failures preserve the previous selection and assignments and clear the busy state. Native dialogs do not hold the mutation queue or expire on the short bridge-response timer. There is no archive extraction or runtime network request.

Snapshots carry all photos so old assignments can still render when another set is selected. Student photo IDs remain numeric; Scientists and imported photo IDs include their immutable set identity. Existing preferences default to Students while preserving enabled/font values and saved decisions.

Feature: `ui.student-design`. Scientists asset and host acceptance is source-scoped; installed-profile and Linux/macOS runtime acceptance remain separate.
