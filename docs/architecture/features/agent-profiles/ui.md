## Instruction package workbench

Status: `partial` for the standalone development surface. The [package workbench contract](editing.md#package-development-workbench) owns package/profiles and activation semantics. Use neutral typography, restrained borders, rounded cards and semantic light/dark tokens. The standalone page title is `Agent 프로필`; its former introductory sentence, equip buttons and request-timing helper are omitted. Saved profile cards themselves support drag, click and keyboard activation. Uniform horizontal image/title/description cards form a responsive grid. A detail dialog provides complete content and accessible keyboard navigation. Stored profiles have drag and keyboard/click alternatives for equipping the current project's single active slot. Background GitHub progress stays in a small corner status and does not replace or disable the catalog. Source-mode and project download-target controls are absent; the visible project context identifies whose profile slot is being edited. The existing library remains a secondary collapsed area beneath the catalog. Feature: `ui.instruction-settings`.

  The profile composer uses a wide two-column dialog: ordered vertical slots on the left and a searchable categorized resource list on the right, stacked at narrow widths. Core harness identity and builtin profiles are read-only. One profile list and composer serve ordinary requests and Team/Direct, with allowed-role choices. Clicking a profile card opens its view/editor; a top-right ellipsis menu offers duplication and deletion for editable personal profiles. Deletion requires an explicit confirmation dialog. A separate small activation/drag control preserves project profile activation. Profile names reserve a circular image area with an icon fallback. Team cards open their configuration editor on click, keep deletion in the same ellipsis pattern and reserve a full-width 4:3 image above their text with a team icon fallback. Local PNG/JPEG/WebP selection, preview and removal use the existing bounded image validation. Resource addition supports drag and click/keyboard alternatives; ordered instructions have explicit move controls. Provider/model/reasoning fields expand inline without their own enclosing card. One `저장` action persists edits; slot and profile diagnostics distinguish saved invalid edits from the last valid applied configuration. Full skill descriptions remain accessible while resource rows show a short preview.

## Team and Direct role profiles

Status: `partial` for the source development surface. The [role profile contract](roles.md#role-profiles-for-team-and-direct) owns session creation and instruction semantics. The unified composer exposes allowed roles alongside the profile's resources and optional model settings. Built-in profiles are read-only and can be duplicated. Ordinary conversations activate one Root-compatible profile per project; other role-only profiles remain visible and editable but have no project activation control. Team presets select one Lead and allowed root/subagent profiles from the same library. Direct common settings select one Root-compatible profile and multiple Subagent-compatible profiles, with each slot filtered by its allowed role. Created Teams retain copied profiles with immutable identity and allowed roles; edits affect newly created children. Use the existing neutral light/dark controls and dialogs. Features: `ui.role-profiles`, `ui.team-lead`.

Common presentation policy: [UI change guidance](../../shared/ui-principles.md#ui-change-guidance).
