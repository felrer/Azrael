# 작업 메모리

Status: `current`. 로컬 저장소와 native 도구, 선택형 프로필 지침을 구현한다. 검증 범위와 미확인 항목은 [작업 기록](../../work/FK-01-task-memory/01-plan.md)이 소유한다. 제품 패키징·설치와 실제 에이전트 작업의 비용 절감 측정은 별도다.

## 목적과 기록의 원본

root와 직접 생성한 subagent는 하나의 작업 메모리를 공유한다. root가 같은 배경을 매번 다시 작성하는 대신 필요한 항목과 버전을 지정하고, 작업자는 자신의 발견·차단·결과를 직접 게시한다. 다른 작업자가 재사용할 수 있는 맥락이 목적이며 모든 도구 실행을 보관하는 일지가 아니다.

| 정보 | 원본 |
| --- | --- |
| 요구사항·승인·공통 결정·완료 기준 | 기존 계획과 담당 설계 문서 |
| 조사 결론·실패 원인·차단·담당 작업 결과 | 작업 mem의 작성자별 항목 |
| 실행 로그·검증 산출물 | 기존 산출물 소유자, mem은 관련 근거 참조 |
| 제품의 지속적인 구조·운영 계약 | architecture·ops 담당 문서 |

계획에는 현재 단계와 수용 결과를 요약하고 상세 mem을 연결한다. root는 작업자가 작성한 결과를 덮어쓰지 않고 공통 context에서 근거와 함께 참조한다. 기록된 제안이나 실행 결과가 요구 변경 승인으로 승격되지는 않는다.

## 저장과 역할

사용자가 정한 기존 작업 폴더의 `mem/`이 저장 위치다. `task_memory`는 명시적 절대 `work_dir`를 사용하므로 작업자가 다른 worktree에서 실행해도 같은 폴더를 지정한다. 자동으로 cwd의 다른 작업 메모리를 선택하지 않는다. 메모리는 작업 소속이며 작성 세션 ID는 도구가 부여한다.

root만 작업 저장소를 초기화하고 `context`를 작성한다. `finding`과 `task`는 각 세션이 자기 항목을 작성·갱신한다. 모든 항목의 수정은 원래 작성자에게 제한하며 종류는 변경할 수 없다. 작성자의 신원은 native 세션에서 결정한다. 접근 경계는 명시한 작업 경로와 기존 파일 권한이다. 초기화한 root ID는 생성 출처이며 접근 권한 목록이 아니다. 세션 재개나 root 교체 시 같은 작업 경로의 기록을 재사용한다. 새 root는 이전 기록을 참조하는 자기 context를 만들며 다른 작성자의 기록을 묵시적으로 이전하거나 덮어쓰지 않는다.

저장 구조는 `owner.json`, OS 자문 잠금인 `store.lock`, `entries/<UUID>/<revision>.json`이다. 각 버전은 불변 전체 스냅샷이며 최신 번호가 현재 버전이다. 새 항목 ID·작성자·시간·버전은 도구가 관리한다. 이전 버전은 후속 작업의 고정 입력으로 읽을 수 있다. 병렬 작성은 저장소 잠금과 예상 버전 검사로 조정한다. 충돌은 기존 내용을 읽어 조정한 뒤 재시도하며 조용히 덮어쓰지 않는다.

## 도구와 전달

- `init`: root가 기존 작업 폴더에 저장소를 초기화한다. 같은 소유자로 재실행할 수 있다.
- `list`: 본문 없는 항목 메타데이터를 제한된 페이지로 읽는다. 선택적으로 종류를 제한한다.
- `read`: 항목 ID와 선택한 버전의 본문·근거·범위·불확실성을 읽는다. 버전 생략 시 최신을 읽는다.
- `write`: 제목·본문·근거 배열·적용 범위와 선택적 불확실성을 작성한다. 생성은 `expected_revision:0`, 갱신은 기존 ID와 읽은 버전이 필요하다. 응답은 본문·근거를 반복하지 않고 ID·버전 등 저장 확인만 반환한다.

root의 배정에는 작업 목표·변경 소유권·제약·완료 기준과 함께 `work_dir`, 필수 항목 ID와 정확한 버전을 포함한다. 작업자는 해당 항목을 읽은 후 의존 작업을 시작하고 부족한 맥락만 추가 조회한다. 필수 기록을 읽지 못하면 기존 부모 요청 경로로 보고하며 다른 버전으로 조용히 대체하지 않는다.

결과의 상세 내용은 mem에 한 번 작성하고 메시지에는 필요한 결론과 참조를 보낸다. mem 쓰기는 부모 알림·판단 요청·완료 이벤트·재개 신호가 아니다. 기존 협업 프로토콜과 사용자 진행 보고를 유지한다. 새 context 자동 주입, 별도 Observer, 벡터 검색과 클라우드 동기화는 제공하지 않는다. 엔진의 전역 장기 기억과 저장소·활성화를 공유하지 않는다.

## 프로필 조립

기존 프로필 구성요소에서 `task-memory-root` 또는 `task-memory-subagent`를 선택한다. 각 구성요소는 공통 작성 규칙 다음에 해당 역할 지침을 조립한다. 원본 공통 규칙은 한 파일로 유지한다. 역할에 맞는 구성요소 하나를 선택하는 구성이 기본 사용법이며, 여러 역할 조각을 선택해도 실제 native 역할에 해당하는 책임만 적용한다. 공통 파일의 전역 중복 제거는 기존 composer 계약을 바꾸지 않는다.

두 리소스는 기본 비선택 상태다. 기존 프로필·대화·설치 설정을 자동 변경하지 않는다. 기존 저장·버전 핀·선택·materialization 경로를 재사용한다. 도구 미지원 상태에서는 조각이 메모리 작업을 요구하지 않는다. 리소스 선택이 역할·도구·파일 접근 권한을 부여하지 않으며 자식 세션은 자기 프로필을 사용한다.

## 권한·실패·수명

일반 도구 정책과 선택한 로컬 실행 환경의 파일 읽기·쓰기 및 읽기 거부를 그대로 적용한다. 읽기 전용 세션은 기존 저장소를 읽을 수 있으나 초기화·쓰기 권한은 얻지 않는다. 원격 환경의 경로를 로컬 호스트 파일로 해석하지 않는다. 검출한 심볼릭 링크와 Windows reparse 경로를 거절한다. 표준 경로 검사와 자문 잠금은 악의적인 외부 프로세스의 동시 파일 교체를 완전히 방어하는 경계가 아니다.

저장 요청은 필드·파일·목록 크기를 제한하며 알 수 없는 필드를 거절한다. 잠금 경합은 busy로 반환한다. 임시 파일을 동기 저장한 후 불변 버전으로 게시한다. 중단으로 첫 버전 없는 항목 폴더가 남으면 일반 목록에서 `incomplete:true`로 표시하고 종류별 목록에서는 제외한다. 읽기·갱신은 명확히 실패하며 기존 자료를 삭제하지 않는다.

mem은 합의된 작업 기록이며 자동 만료·삭제 대상이 아니다. 정리·이관은 작업 기록과 기존 산출물 수명 절차를 따른다. 로그나 비밀 값을 복제하지 않고 필요한 근거만 연결한다. 삭제 API·소유권 이전·과거 계획 기록의 자동 이전은 이 범위에 포함하지 않는다.

기능 보존 ID: `tool.task-memory`. 반복 검증과 사용 예는 [운영 지침](../ops/task-memory.md)을 따른다.
