# 연속 작업 시간

Status: `partial` — 턴 관계·재개 횟수·시간 기록의 Windows native 계약과 사용자 메시지 아래 시간·턴 한 줄의 소스 및 Windows 격리 React/CSS 렌더링은 검증됐다. 실제 VS Code 호스트·현재 패키지 설치와 Linux/macOS 수용은 별도 검증한다. 근거는 [작업 기록](../../work/AL-01-resume-task-group-reliability/01-plan.md)에 둔다.

## 작업과 사용자 흐름

한 대화에서 자동 재개로 이어진 작업을 묶어 총 시간과 턴 수를 표시한다. 같은 연속 작업에서 모델이 `azrael_agents.defer_root`로 대기를 성공적으로 등록한 횟수가 3회 이상이면 묶음을 표시한다. 세 번째 등록 시점부터 첫 턴의 작업 시간과 대화 범위를 포함한다. 0·1·2회에는 이 기능의 요약·선·조회 오류 배너를 표시하지 않는다.

성공 등록은 고유 reservation ID와 대기 시작 시각이 있는 durable `rootResumeWait`로 확인하며 중복은 한 번만 센다. 이후 취소·교체·차단되어도 이미 성공한 등록 횟수는 유지한다. 준비 중이거나 실패한 호출, 하위 에이전트의 별도 대화와 다른 세션 링크 읽기는 횟수에 포함하지 않는다. 현재 활성 예약 목록 대신 전체 턴 기록을 사용하므로 종료된 예약도 새로고침 후 동일하게 판정한다.

자동 재개는 `turnTrigger=root_resume`, 부모 턴과 root 계보를 함께 확인한다. 새 사용자 입력으로 시작한 턴은 같은 root ID를 이어받았더라도 별도 자동 작업의 시작이다. 기존 기록에 관계 정보가 없으면 자동 연결을 추정하지 않는다.

연속 작업의 첫 사용자 메시지 바로 아래에 `총 6시간 56분 · 29개 턴`처럼 시간과 턴 수를 보조 텍스트 한 줄로 표시한다. 화면의 다른 턴·메시지·도구·첨부는 native 대화 흐름을 따른다. 시간 내역 표, 작업 번호, 경계 편집, 접기·펼치기 컨트롤과 장식 테두리·선은 제공하지 않는다. 수동 작업 경계 preference를 읽거나 쓰지 않으며 기존 저장 데이터는 보존한다.

표시는 native transcript 및 full-turn 사용자 메시지 렌더 경로에 포함되며 사용자 말풍선 바깥의 바로 아래에 배치한다. 행 수·키·순서는 유지하고 기존 가상 목록의 높이 측정을 따른다. metadata의 정확한 첫 턴 ID에 대응하는 실제 사용자 메시지가 로드되어 있을 때 한 번만 표시한다. 첫 사용자 행이 아직 없으면 다른 메시지 아래에 대체 표시하지 않는다.

전체 대화 기록의 시간 메타데이터를 집계하므로 과거 메시지 본문의 부분 로드와 총 시간을 분리한다. 시간 조회와 live 갱신은 가상 행보다 오래 유지되는 목록 소유자가 담당한다. 스크롤로 메시지가 사라졌다 다시 나타나도 기록을 다시 조회하지 않는다. 본문은 기존 가상 렌더링·부분 로드·검색·스크롤 기준점 및 최신 턴 판정을 사용한다. 시간 표시를 위해 전체 본문을 새로 가져오거나 별도의 행 측정 경로를 만들지 않는다.

## 시간 의미

전체 작업 시간은 실행 구간과 기록된 자동 재개 대기 구간의 합집합이다. 사용자의 다음 메시지를 기다리는 턴 사이 공백은 제외한다. 모델 실행, 도구 실행, 빌드와 검사에 소요된 시간은 실행 구간에 포함한다. 병렬 구간과 중복 기록은 한 번만 계산한다. 하위 에이전트의 실행 시간을 root 시간에 따로 더하지 않는다.

진행 중인 실행과 자동 재개 대기는 현재 시각까지 갱신한다. 종료된 실행은 엔진의 `durationMs`를 사용하며, 종료된 대기는 기록된 시작·종료 경계를 사용한다. deferred 턴의 실행 시간은 defer 경계에서 고정되며 대기 시간만 증가한다. 완료·중단·실패 뒤 시간은 증가하지 않는다.

사용자 응답 대기의 기본 경계는 앞 턴의 실행·자동 대기 종료부터 다음 사용자 턴 시작까지이다. 턴 내부 도구 승인이나 입력 요청은 엔진의 실행 시간 계약을 따른다.

과거 기록의 시작 시각은 초 단위일 수 있지만 실행 시간은 밀리초 측정값이다. 같은 초에 시작된 순차 턴은 시작 시각의 정밀도와 기록 순서를 고려해 각 측정 시간을 보존한다. 기록 순서·시각 정밀도·대기 경계를 함께 만족시킬 수 없으면 부분 집계로 표시한다. 원본 시각은 변경하지 않는다.

시작 시각·측정 시간·대기 종료 경계가 없는 기록은 추정치로 채우지 않는다. 확인된 시간은 `확인된 시간 · 턴 수`로 표시하고 보조 설명에 일부 기록의 부재를 알린다. 전체 메타데이터를 불러오지 못한 경우에도 확인되지 않은 시간을 전체 총계처럼 표현하지 않는다. native 진단과 다음 live 상태 갱신에서 조회 복구를 처리한다.

## 소유권과 적용 범위

엔진은 턴 시간과 root resume 대기 경계를 소유한다. 저장된 TurnStartedEvent attribution을 history builder·저장 projection·metadata-only/full wire Turn·live 알림에 전달한다. `parentTurnId`·`turnTrigger`는 정보가 없는 기록에서 null이며 root ID만으로 자동 재개를 만들어내지 않는다. projected history의 추가 열과 projection 버전 변경은 원본 rollout을 보존한 transactional lazy 재구성을 사용한다.

웹뷰는 기존 `thread/turns/list`의 모든 메타데이터 페이지와 live 턴 갱신을 결합하며 연속 자동 작업의 구성과 집계를 소유한다. native background history 요청·timeout·logger 경계를 재사용하고 단순 조회로 전체 메시지 본문을 가져오지 않는다. 미로드 thread·첫 사용자 메시지 전 미생성 기록·ephemeral 미지원과 일반 조회 실패를 구분한다. 턴 시작·예약·상태 변경에서 갱신하며 시간 tick이나 스크롤로 조회를 반복하지 않는다. 정상 snapshot은 실패 이후에도 보존하지만 확정 전체 총계로 표시하지 않는다.

기록된 순서를 유지하면서 누락된 live 턴을 공통 턴·부모·시각 기준의 위치에 삽입한다. 관계 정보는 clock/status와 독립적으로 보존한다. 완료 상태를 오래된 live 상태로 되돌리지 않고, reservation ID가 다른 revision을 서로 비교하지 않는다. 선후 관계가 모호하면 기존 기록을 유지하고 부분 집계로 표시한다. 대화 전환·종료 이후의 응답은 이전 소유자에게만 속하며 화면에 늦게 게시하지 않는다. 진단은 method·대화/host 식별자·오류 코드·상태만 기록하고 메시지 본문·도구 인자는 추가하지 않는다.

Windows x64, Linux x64와 macOS ARM64의 로컬 VS Code 대화에 공통으로 적용한다. 원격·컨테이너 환경의 수용은 이번 범위에 포함하지 않는다. native OpenAI 스타일의 기존 보조 텍스트·색상 토큰과 사용자 메시지 레이아웃을 재사용하며 밝은·어두운 테마에서 검증한다.
