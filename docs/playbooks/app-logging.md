# 앱 로그와 오류 진단 Playbook

적용 범위: 새 앱의 초기 구현, 로깅 자체를 추가·변경하는 작업, 로그 부족으로 오류 원인을 추적하기 어려운 진단 작업에 적용한다. 일반 구현·수정 작업에서는 변경한 경로의 기존 로그로 실패를 추적할 수 있는지만 확인하고, 그 밖의 로깅 보완은 승인된 계획에 포함된 경우에만 수행한다.

## 기본 원칙

- 앱은 오류 발생 시 실행 흐름과 원인을 추적할 수 있는 로그 시스템을 갖춘다. 신규 앱은 초기 구현에 포함한다.
  기존 앱에서 로그 부족을 발견하면 근거와 보완 범위를 작업 계획의 결정 사항으로 제시하고, 승인된 범위만 보완한다.
  전체 도입이 필요한 경우 남은 범위와 도입 계획을 명시하며, 일부 경로 확인을 전체 구축으로 보고하지 않는다.
- 기존 로거, 프레임워크·플랫폼의 로깅 기능과 수집 경로를 먼저 확인해 재사용한다. 앱 전반의 로그 수준,
  필드와 출력 정책을 일관되게 관리하고, 임시 console 출력이나 개별 파일 쓰기를 상시 진단 수단으로 방치하지 않는다.
  로깅만을 위해 불필요한 자체 프레임워크나 외부 서비스를 도입하지 않는다.

## 기록할 정보와 경계

- 검색·필터링할 수 있는 구조화된 기록을 사용한다. 기본 필드는 시간대가 명확한 시각, 로그 수준,
  구성요소, 안정적인 이벤트 이름, 설명, 앱 버전·실행 환경이다. 플랫폼이 제공하는 공통 메타데이터는 재사용한다.
- 요청·작업·세션 등 실행 단위에 상관관계 식별자를 부여하고 비동기 작업과 프로세스·통신 경계에서도
  관련 기록을 연결할 수 있게 전달한다. 환경에 존재하는 경계에 적용하고 개인정보를 식별자로 사용하지 않는다.
- 시작·종료, 주요 작업의 결과·소요 시간, 상태 전환과 외부 통신·저장소·백그라운드 작업의 실패를 기록한다.
  오류에는 작업명, 오류 종류·코드, 원인 연결과 가능한 스택, 재시도·복구 결과 등 진단에 필요한 문맥을 남긴다.
  처리되지 않은 예외는 실행 환경의 오류 경계에서 수집하며, 포착한 오류도 조용히 삼키지 않는다.
- DEBUG는 상세 진단, INFO는 주요 정상 동작, WARN은 복구 가능한 이상, ERROR는 작업 실패에 사용한다.
  계층마다 같은 오류를 반복 기록하지 않도록 기록 책임을 정하고, 재시도 기록과 최종 실패를 구분한다.
  로그만 남긴 채 성공으로 처리하지 않으며, 사용자에게 표시하는 오류와 내부 진단 상세를 분리한다.

## 출력·보관·안전성

- 개발·배포 환경별 출력 대상, 기본 수준, 상세 로그 활성화·해제 방법을 정한다. 배포된 앱에서도 문제 발생 후
  로그를 확보할 수 있어야 한다. 파일, 플랫폼 로그 저장소, 수집되는 표준 출력 등 환경에 맞는 방식을 사용하고,
  휘발성 개발 콘솔만으로 완료로 판단하지 않는다.
- 저장 용량·보존 기간과 회전·삭제 정책을 정하고 접근 권한을 제한한다. 토큰·비밀번호·인증 헤더·개인정보와
  요청·응답 원문은 그대로 기록하지 않는다. 허용할 필드를 선별하고 오류 객체·URL·스택을 포함한 출력과
  내보내기 경로에 필요한 마스킹을 적용한다. 외부 전송은 프로젝트의 데이터 취급 정책과 허용 범위를 따른다.
- 과도한 반복 기록은 제한·집계하고, 샘플링을 적용하면 오류 추적에 미치는 영향을 명시한다. 로깅이 UI나
  주요 실행 경로를 막지 않도록 버퍼·큐에도 상한을 둔다. 저장 실패나 수집 장애가 재귀 오류나 앱 실패로
  번지지 않게 하고, 로그 유실을 확인할 최소 수단과 종료 시 기록 처리 방식을 정한다.

## 검증과 운영 문서

- 로깅을 추가·변경한 경로는 대표 오류를 재현해 실제 출력에서 실패 지점, 원인과 관련 실행 흐름을
  추적할 수 있는지 확인한다. 적용 환경의 보관·조회 또는 내보내기 경로와 민감정보 제외를 검증하고,
  저장 실패·용량 제한 등 변경에 중요한 위험은 필요한 범위에서 확인한다. 로거 호출의 존재만으로 통과시키지 않는다.
- 프로젝트 운영 문서에 로그 위치·조회 방법, 수준 변경·원복, 보존·삭제, 안전한 수집·공유 절차를 기록한다.
  오류 보고에는 발생 시각·시간대, 앱 버전, 재현 단계, 상관관계 식별자와 필요한 로그 범위를 연결한다.
  앱 진단 로그의 운영 정책과 작업 중 테스트·빌드 로그의 산출물 보존 정책은 각각 해당 소유 문서에서 관리한다.
