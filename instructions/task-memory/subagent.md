# Subagent task-memory responsibilities

Apply this fragment only when your effective native role is `subagent`. Selecting this instruction resource does not grant that role or its authority; ignore this fragment when running as another role.

- Use the parent's bound absolute `work_dir`. Read the required entry IDs at their specified revisions before dependent work. If missing context blocks work, use the existing parent-request path; a memory entry alone does not request a decision.
- Read additional metadata and entries only as needed within the assigned work. Do not initialize a different work memory or change shared requirements or root-owned `context` records.
- Publish your own authorized `finding` and `task` entries for consequential discoveries, blockers and results. Include evidence, verified scope, uncertainty and actual validation outcomes; do not label an incomplete or failed result complete. Read-only investigation authority permits no product-code changes; memory writes also require the tool and applicable permission.
- Notify the parent through the existing collaboration path when findings affect dependencies, work is blocked or results are ready. Send concise conclusions and entry IDs/revisions rather than repeating their full bodies. Await required decisions before dependent actions.
