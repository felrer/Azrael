# Stage 2 — Current-window control

Execution is in the user’s session; app input can interfere with their work. App approval and task-stage authority are separate. Use only the exact selected target and advertised operations.

`capture` returns the target's own fresh image, including when another window covers it. `inspect` reads accessibility state without an image. Neither operation should raise the target window. Examine a fresh observation before an individual action and use its `observationId` and `elementId`. Supported semantic actions use the element's declared Invoke, Value, Toggle, Selection, ExpandCollapse or Scroll patterns. Value replacement is not physical typing. An action, resize or macro invalidates older references. Unsupported operations must be reported.

A tool failure with `recovery: observe_again` retains the selected target and discards older element references. Refresh `status` and occupancy, then decide whether to obtain a new `capture` or `inspect` or report a persistent failure. `observationRequired: true` requires a fresh successful observation before input. New observation is permitted, not guaranteed to succeed; do not interpret a failure as success or automatically replay the rejected input or completed macro steps. Read-only accessibility, capture and provider/connection failures and confirmed input precondition rejections can use this recovery. Respect unsupported capabilities and capture protection. A genuine paused state, user stop, revoked authority, changed target identity or `mutationOutcome: unknown` retains its separate recovery requirements.

Use `run_task_macro` for a known sequence of semantic actions, condition waits, assertions and final capture. It accepts an immediate definition or the ID of a saved definition. `save_task_macro` stores reusable definitions; `list_task_macros` retrieves them. Pass variable text as execution parameters, not saved secrets. Selectors match elements by name or AutomationId, type and optional ancestor; the executor resolves them afresh at each step. Ambiguous or unavailable targets stop the sequence. Definitions are limited to 32 steps, a 20-second run and 10-second individual waits. Split longer work at verified checkpoints. Respect per-step results, cancellation and partial completion; do not replay an uncertain mutation.

When `elementsTruncated` is true, the image remains usable but accessibility results cover only part of the tree. A missing element is not proof of absence and a selector match is not proof of uniqueness. Task macros stop on incomplete accessibility observations. Individual actions can use exact element references from the current partial observation after verifying their identity and purpose.

`press_key` uses experimental window-directed message delivery only when the requested element owns an exact native HWND inside the selected window. Virtual controls without an independently owned HWND are unsupported; never substitute an ancestor or root window to target an individual field. Supported named keys are Return, Tab, Escape, BackSpace, Delete, Left, Right, Up, Down, Home, End, PageUp, PageDown and space. Modifiers and system shortcuts are unsupported. A successful enqueue reports delivery, not confirmed application processing. A key step in a macro requires a postcondition. Verify resulting state before proceeding. Do not change global keyboard state, focus, cursor or clipboard to make an unsupported key work.

Minimization pauses observations and control. `status` reports `window.minimized`, `pauseReason` and `restoreAllowed`; affected calls return `window_minimized`. When fresh occupancy is available and `restoreAllowed` is true, use `restore_window` with the selected `targetId` to restore that exact window without requesting activation. Then obtain a fresh capture or inspect before acting. Restoration discards prior observations and does not replay any input or macro. An unsuccessful or uncertain restore must be reported rather than repeatedly retried. A user stop (Escape or the stop button), revoked approval or another error pause requires explicit user resume and cannot be cleared through `restore_window`. Separate top-level dialogs require discovery and selection; they do not automatically belong to the parent observation. Closed or replaced windows require a fresh selection. Never treat an unavailable or cached frame as a live screenshot.

`resize` uses outer-window dimensions in DIP units and preserves position. Named macros from `status` contain bounded size steps. `run_size_macro` applies only a user-defined macro to the selected target. Report actual size or an error; do not change another window, display settings, pointer settings or Z order to force success. A rejected size stops the macro. Already-delivered application actions are not guaranteed reversible.

Stop, revoked approval, changed window identity and stale observation invalidate ongoing work. Do not use a late response after cancellation. Tool errors about permissions retain the native permission profile; do not elevate or change it to full access. The restricted tool surface does not authorize credential, security or destructive actions beyond the user's task.

An app can cause focus changes even when no-activate APIs are used. If the host reports target interference, stop rather than taking focus back. Ordinary foreground changes in unrelated applications are permitted. Concurrent editing of the selected target can still conflict. Sampling before and after an action cannot rule out transient activation or prove who caused a focus change. Capture, semantic actions and key delivery are separate capabilities; tool availability does not establish application-specific acceptance.

On Windows, the explicit foreground-target stop shortcut is Ctrl+Alt+Shift+F12. Bare Escape remains an app key. When the shortcut cannot register or fit the overlay, use the Azrael stop control; do not invent a fallback shortcut.
