# Work Maps

Find code areas, stable entry points, component relationships, and execution roles relevant to a task.

Keep each map focused on a useful reading path: the task signal, relevant code roots or symbols, the owning contract
document, and the verification or operation entry point when applicable. Link to owners rather than repeating their
commands, defaults, or runtime state.

Add separate role or platform maps only when the project's actual structure needs them. A script or library may need
only a short code map; a multi-runtime project may need several role-specific routes. A map should make the next
useful read clear without requiring every linked document to be read in full.

No detailed maps are registered yet. Link them here when code structure or execution roles need a maintained guide.
