# Changelog

## Unreleased

- 위임 시 자연어로 요구사항을 함께 전달하고, 필요한 경우 코드 조각·평가 알고리즘·입출력 예시·기존 테스트 참조를 선택적으로 덧붙이도록 했습니다.
- 완료 또는 blocker 보고 전까지 root의 모든 상태 확인을 금지하고, 개입 예외와 완료 후 수정 요청 일괄 전달 기준을 명시했습니다.
- 기본 역할 모델을 `gpt-6-luna`·`gpt-6-sol`로 바꾸고, `spawn_agent`에 `agent_type`을 항상 명시하도록 했습니다. 문서를 현재 내용 기준으로 그 자리에서 고치는 문서 편집 규칙을 추가했습니다.
- 작업 문서를 세션별 `nn-brief.md`에서 작업별 단일 `nn-plan.md`로 바꿨습니다. 유틸리티 명령은 `new-session --plan-file`과 `new-plan`이며, 기존 brief는 보존되고 다음 번호 계산에 포함됩니다.
- planning에 상태 줄, 결정 사항의 정의, 방향을 바꿀 질문이 있을 때의 조건부 확인, 질문 답변과 계획 승인의 구분, 구현 가능성 부족 시 선택지 제시, designing 명시 호출, 구현 중 계획 이탈 처리와 완료 조건을 추가했습니다. 실행 준비 참조 문서를 포함하고 연결했습니다.
- designing과 project-bootstrap 템플릿·검증 기준을 단일 plan 체계에 맞췄습니다.
- designing은 설계 문서에 최신 설계만 남기도록 했습니다. 변경 과정 서술과 날짜별 단락을 금지하고, 상태는 문서·절 단위로 한 번만 표시하며, 검증 근거는 작업 계획이나 운영 문서에 두고 링크합니다. 반영 후 확인 항목을 추가했습니다.
- 작업 Playbook에 구현 중 계획 이탈 처리와 검증 근거 위치 규칙을 추가했습니다. 템플릿의 문서 상태 규칙에서 날짜 기록 요구를 링크 방식으로 바꿨습니다.

## 0.3.0 — 2026-09-12

- 공용 작업 Playbook을 bootstrap assets에 포함했습니다. 재사용, 계획에 한정된 레거시 호환, 데이터 마이그레이션, 파일 구조, 검증과 정리 기준을 제공합니다.
- project-bootstrap은 작업 Playbook을 기본으로 가져오며, 기존 작업 지침이 있으면 해당 소유 문서에 통합합니다. 출처 기록, 프로젝트별 조정과 반복 실행 시 중복 방지를 포함합니다.
- planning에 레거시 코드·테스트·실행 스크립트 정리 계획, 장기 작업의 파일 구조 관리와 완료 시 정리 확인을 추가했습니다.
- 공개 배포본은 개인 Vault 없이 설치할 수 있도록 상대 경로와 기존 세션별 brief 규칙을 유지합니다.

## 0.2.1 — 2026-09-11

- 공통 지침에 증거 수준에 맞는 결론과 반례 처리 원칙을 추가했습니다. 미확인을 불가능으로, 도구의 존재를 정상 작동 확인으로 취급하지 않도록 했습니다.
- 사용자 설명·화면·실행 결과가 기존 결론과 충돌하면 관련 주장을 재검토하고 정정 내용과 남은 불확실성을 명시하도록 했습니다.

## 0.2.0 — 2026-09-08

- planning, designing, project-bootstrap과 필요한 스크립트·참조 문서·템플릿을 배포에 포함했습니다.
- README를 설치부터 프로젝트 초기화, 방향 확인, 설계, 위임과 검증까지 이어지는 안내로 확장했습니다.
- 세 스킬의 description 원문과 planning 사용을 명시적으로 지시하는 권장 예시를 추가했습니다.
- bootstrap 배포본의 개인 경로 의존성과 이전 brief/plan 규칙을 현재 planning 체계에 맞췄습니다.
- 공통 지침에 스킬 사용 흐름을 연결했습니다. 동시 실행 한도 예시는 현재 설정값인 8로 설명합니다.

## 0.1.0 — 2026-09-07

- 개인 운영 지침에서 공통 근거·출력 규칙과 부모의 위임·통합 규칙을 추출했습니다.
- 탐색 및 구현 역할 두 개의 공개용 복사본을 정리했습니다.

- 적용 방법, 가상 예시, 원본 대비 변경 사항과 검증 한계를 기록했습니다.
